# 自行车租赁需求分析：下一项完整科研与办公工作

状态：2026-10-15 已取得官方数据并形成任务候选，尚未形成模型运行结果。本任务转向不同于 COMAP 的来源，用完整成果观察工作收敛与后续学习，不继续修补奥运同题来追求成功。

## 工作目标

为共享单车运营人员完成一份可复核的历史需求分析与短期预测材料：识别工作日/非工作日和季节性需求差异，判断可用于次日需求预估的方法是否优于简单规则，并形成能实际打开的分析工作簿、简明报告及从原始输入重建结果的源码。方法、工具和工作顺序由 Agent 自主决定；保留遇到的真实问题及有效部分成果。

来源为 [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset)，Hadi Fanaee-T，2013，DOI [10.24432/C5W894](https://doi.org/10.24432/C5W894)，CC BY 4.0。包含 Capital Bikeshare 2011–2012 年的小时/日租赁量、天气与日历变量。数据说明与授权按官方 Readme 和来源页保留。

[来源清单与哈希](source.json)记录实际下载：hour.csv 17379 条、day.csv 731 条，均覆盖 2011-01-01 至 2012-12-31。官方页面实例栏显示 17389，与实际下载文件的 CSV 数据记录数不同；复现以保存的文件和哈希为准，不手改数据以迎合页面数字。原始 ZIP、CSV、Readme 和来源清单位于本地 `/mnt/e/CoEvo/data/uci-bike-sharing`。

## 任务内容与科学边界

- 核对日表、小时表与字段说明，检查实际日期/小时覆盖、计数口径及两表是否一致；缺少小时记录不能未经证实视为零需求。
- 解释需求的日历规律及天气关联，提供必要图表和运营含义；关联分析与可部署预测分开说明，避免将季节、年份变化或用户构成混淆为因果效应。
- 对日总量开展时间顺序回测。以 2012-10-01 至 2012-12-31 为最终开发评价区间，方案与调参使用更早日期；次日预测只使用当时可得的信息，允许使用此前已观测的真实历史需求。比较至少一个简单基线与自主选择的方法，报告误差及关键失败情形。
- `casual`、`registered` 是当日总量组成，不能作为次日需求的同期输入；同期真实天气也不能冒充提前获知的天气预报。若开展有同期天气的解释性分析，明确区别于事前预测。
- 工作簿、报告与实际运行结果保持一致；交付原始输入到结果的可运行路径及未解决限制。无需为了增加算法数量或文件数量扩大范围。

这些要求定义用户工作和信息可见性，不规定内部学习提议或思考的固定 schema。研究者不向模型提供参考实现或预先代算的结论。

## 评价和执行范围

独立评价从原始文件重新核对聚合、时间划分、预测输入可见性、基线/模型误差及报告结论；在干净副本实际执行模型保存的源码，核对工作簿和数值。首次观察重点是完整成果、恢复行为、真实成本与最终自述，而非每次工具调用的成功率。没有预设“必须胜过基线”的成功结论；若优势不足，准确报告也可以构成有效研究交付。
