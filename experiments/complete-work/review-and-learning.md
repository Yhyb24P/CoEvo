# 成果复核与后续学习

每轮提交用任务要求进行实质复核，保存审阅者、实际文件/表格/日志引用、结论和剩余障碍。verify 产生自动证据及 review_pending；task_success 初始为空，由后续有依据的审阅补充，不从进程状态自动赋值。不要为了填满此表强行要求每项成功。

软件复核：需求行为和冻结回归；API 兼容与改动范围；新增测试是否真正覆盖冲突；文档和工作报告是否与实际运行一致。科研复核：输入与分析样本对应、缺失/重复处理；species/island 的重叠与可识别性；主要 pooled/adjusted 数值、样本数及区间独立重算；敏感性结果；报告与表图一致；结论和因果限制。对随机分析记录种子，数值比较采用方法对应的容差，图像字节差异本身不判科学失败。

## 来源复用

既有 Marko 任务、MCM 失败和多工作区可见 Codex 交互保留在各自来源簇。本轮把前两者作为不同来源的历史工作，新的 frontmatter 和 penguins 不改标为独立 H。Codex 片段可以提供参考的调试、检验与科研工具行为；采用具体片段前确认其输入可重建、实际结果和原始辅助身份，不重新全盘导出或因任务类型预先排除。教师正确示范可形成有教师标记的监督，不能计入小模型自主成绩。

## 按实际证据推进 Q1/Q2/Q3

每个可用片段以原生 session 消息/工具调用 ID、当时文件状态、真实输出和复核依据定位，不要求改写成固定决策 JSON。未运行代码、错误统计及自述成功保持为失败/待确认材料；有效部分即使整项任务失败也可保留。

Q1：从核实片段提出可复用经验，保留条件和反例；在不同来源的后续完整工作分别观察无经历、原始经历和提炼经验。此前原生 Pi 比手工重建历史更适合保持真实续接；跨任务注入须另记信息和成本。

Q2：对已核实目标记录原始来源、辅助者、正确的 assistant 续接及监督范围，再复用现有完整行为 SFT/Replay 路径。D 反馈维持 D 身份，不事后改成未曝光 L；开发训练若获授权，应明确其 D 性质。参数收益以新的真实工作、旧能力和成本判断，部分正确目标不等于整段轨迹可全部监督。

Q3：收集 Agent 自主提出的经验或 Harness 修改，记录提出时可见反馈、实际改动和预算；先核验它是否有效，再在另一来源的未来工作观察。研究者改动、Agent 提议和学习后更善于改进分别归因。没有后续收益时保留负结果。

第一轮结束后据有效成果与失败类型决定学习路径，不预先指定必须训练、必须压缩经历或必须搜索 Harness；也不要求三个问题严格串行完成。
