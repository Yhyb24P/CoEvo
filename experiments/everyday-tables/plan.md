# 表格清理与核对：开发及训练数据路径试跑

用户已要求开始推进，并选择表格清理与核对作为首个日常工作方向；本批登记日期为 2026-10-14。此批使用研究者制作的非私人、可复位 CSV 案例，不声称是真实个人材料或真实用户纠错。沿用 Qwen3.5-4B、现有 Pi SDK 和独立检查；不启动正式 RSI，不使用 H。

事前登记三条不同程序结构的合法 L 任务：列名/金额规范化、两表对账、分类汇总；D 边界任务为缺汇率及只读授权。这些案例不是先前 Marko D 数据的重新划分。原始输入只读，只允许写事前列明的输出文件，终端和文件工具执行同一权限范围。所有派生目标继承来源簇及原集合；当前只提供实例级开发证据，不作为结构留出的正式泛化面板。

每个 Agent episode 上限 12 次工具操作、120 秒、每次生成上限 2048 token。W0 执行后，由外部检查器核对 CSV 内容、原文件保持、实际工具结果及正常停止。成功 episode 不能自动授权所有 Assistant 文本：读取、正确写入、受控终端行为和结束目标分别核验，失败动作及工具观察保留为上下文，不作为正向监督。边界案例的自然语言判断另记录匹配证据，未经充分核验的目标不训练。

在来源和目标核验通过后，允许一次完整行为监督的数据路径资格更新：只使用此批合法 L 目标，监督 token 不超过 5000、最多 24 步、单次墙钟上限 900 秒、seed=17、一次遍历、BF16 LoRA r=16、alpha=32、dropout=0、原文本投影模块范围不变，学习率 1e-5。保留原始 W0，不自动晋升。先核对实际 tokenizer/mask，再训练，独立重载候选，复测原 G 文件任务和 D 边界任务；保存全部失败及资源。

该更新同时改变数据与学习率，只用于建立可运行的完整行为 SFT 基线，不用于确定旧候选退化的单一原因。局部监督、完整监督、等 token replay 的正式匹配对照和 SRFT 生成筛选后续开展；一次 loss 或参数哈希变化不算能力收益。若候选不足、目标核验失败或预算不满足，保留具体失败，不放宽准入或使用 D 数据补足。

参数更新前的目标准入补充：整体任务失败时，仍可保留逐条独立核验的正确读取或执行目标；失败的完成宣称不监督。Bash 的改动由该步后的输出核验，或由“成功 episode 中唯一可能修改输出的工具调用”核验。反馈分支只监督续接之后的目标，先前动作保留为上下文。证书绑定原始轨迹、前缀、工具 schema、目标和实际状态。

实际数据资格：得到 4 个目标、2 个 L 来源、369 监督 token，只有分类汇总覆盖了读取→实际执行→正常停止。此数据只用于本次 4 步资格更新，不能宣称已建立充分的完整行为训练基线。三条原始 L 任务、两条 D 任务及两次失败反馈全部留存，不使用 D 补训练数据，也不因失败追加参数搜索。
