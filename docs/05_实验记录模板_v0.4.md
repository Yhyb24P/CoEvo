## 2. 数据与曝光清单

| 字段 | 填写内容 |
|---|---|
| 数据版本 / hash | 原始清单、事件和派生内容的版本 |
| 来源簇与程序族 | ID、所属 L/D/V/G/H、任务结构及派生链 |
| 授权政策 | 合成/公开/私人材料类型、store/activate/express/train 政策引用 |
| 候选目标 | 稳定能力、正确 Assistant 目标、loss mask 和环境核验引用 |
| 选择策略 | T1/T2/T3、选择器 checkpoint、分层配额、排序规则与 tie seed |
| 排除原因 | 未授权、测试派生、目标错误、状态不符、重复、长度或候选量不足 |
| 样本组成 | 各族/来源/深度/动作类型计数，目标与前缀 token 分布 |
| 来源隔离 | 原始簇交集、跨集派生、近重复/结构复用检查及处理 |
| 曝光记录 | 哪个角色/程序、何时接触何集合的题目、标签、轨迹或分数 |

H 曝光记录保留题目曝光、分数曝光和基于反馈的后续修改三个字段；“未用于训练”不能代替“未用于选择”。共享候选池还需记录各生成模型配额、池 hash、各组实际看到的相同内容与选中集合。

复用组件的仓库、固定 revision、依赖、接口版本及本地修改引用放入 `code_and_environment_ref`；任务来源、检查器、沙箱版本与许可核查放入相应输入、环境和评价引用。实施阶段 A–D 可在 study 描述中标注，科学 arms 与主对照仍使用研究方案定义。

本节是运行清单的权威字段结构；实现运行器时按此生成可解析清单，字段不适用时说明原因。`effective_config_ref` 指向包含默认值和命令行覆盖的完整解析配置。`environment_and_hardware_ref` 记录 OS、Python/uv、训练框架、驱动与内核、推理后端、构建及实际设备信息；版本未知时不猜填。`artifact_index_ref` 指向产物位置、哈希、访问条件和保留策略，公开清单不含私人原文或凭据。

正式确认性实验记录干净、确定的提交。探索阶段允许 dirty tree，但保留差异和新增源码快照；无 Git 的早期试跑保存源码清单与哈希，并注明版本管理尚未建立。`code_and_environment_ref` 可作为归档入口，不能替代具体源码状态与环境记录。

失败运行同样填写时间、预算消耗与可定位日志。某个训练参数未出现变化，先判断是否符合 LoRA 初始化和模块行为；整条训练只有保存动作、无有效监督或梯度，则记作训练链失败。loss 下降不得单独填为“有效学习”。

运行层归因记录采用“原始生成 → parser → 参数/授权 → 执行 → 返回 → 最终状态”的证据链。先说明已观察到哪一层错误，再提出解释。区分模型错误、工具/网络故障、状态管理错误、检查器缺陷和归因未明；不把全部失败灌入训练池。

## 4. 周期与发布记录

| 周期字段 | 记录内容 |
|---|---|
| 周期起点 | 当前已接受 W/Adapter、K/R 快照、学习流位置 |
| 版本关联 | 软件版本/提交、实验协议与冻结单、模型产物版本及对应 run ID |
| 候选池 | hash、来源配额、生成者、独立核验证据 |
| 选择 | SF/SU 模型与提示、实际调用数/token、被选集合、选择时间 |
| 训练 | 共同预算、replay 来源与比例、从哪个 Adapter 续训、实际消耗 |
| 前瞻任务 | 更新前求解结果及随后可见反馈 |
| 回归 G | 当前与固定初始基线、旧族结果、发布决策依据 |
| 封存面板 | 本周期候选快照、H_cycle 编号、是否尚未评分/解封 |
| 决策 | 接受、保持旧版、候选不足、回归、运行失败或超预算 |
| 导出 | Adapter/合并/GGUF/量化 hash、模板/parser 一致性与部署回归 |
| 后续版本 | 实际部署模型、回滚位置与影响范围 |

发布决策与科学结论分别填写。若 G 很好但 H 不支持泛化，写明部署选择成立而确认性收益不成立。若 H 有参数收益但笔记本导出/时延不满足要求，保留科学结果并不发布该版本。
