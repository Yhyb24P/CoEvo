# 人机交互驱动的小模型 Agent 持续适应与参数学习：研究方案（v0.4）

日期：2026-10-13。实施修订：`workstation-128k-2026-10-13`。本次按当前用户要求改为工作站主实验平台与四阶段实施，模型资格要求 128K+ 实际上下文；笔记本部署后移。保留 K/R/W/S 因素分解及核心对照；既有冻结实验仍按其原协议快照执行。本文规定研究问题和实验比较。数据字段、统计规则、运行参数与文献审查分别见配套协议。v0.3 的模型及设备细节作为候选起点；当前已确定的设备约束为无独显、32GB 内存笔记本与 RTX 5090 工作站。具体模型与训练栈尚未最终确定；本方案中的建议配置与正式研究结论仍待确认。2026-10-13 用户要求暂停实施供云端研究；一次 128K 与 LoRA 工程试跑及候选退化见 [研究快照](../experiments/workstation-rsi/review_snapshot.md)。真实交互作为主要学习来源的时机、独立使用场景和训练触发方式尚待讨论，本次交接不追溯改变冻结试跑。

## 1. 研究判断与贡献边界

研究面向资源受限本地部署的小模型 Agent，利用真实交互、工具执行结果及用户纠错，建立外部经验适应与周期性参数学习机制。工作站承担主实验、Agent 交互与周期训练，笔记本在工作站研究与回归完成后进行最终部署验收。主要开发投入集中在交互信息的适用性、有效期、训练价值及模型对后续选样的反馈；Agent 执行、任务环境、训练和通用评价优先复用成熟组件。复用实现与评价方法不意味着继承其能力结论。

核心问题是：在相同工具、任务、上下文和可比较的计算预算下，具有明确来源与作用条件的系统，能否从连续交互中获得可迁移收益，并控制错误沿用和负迁移；其中，哪些收益来自外部状态，哪些来自经验检索，哪些确实来自参数更新？

首选底座为 `Qwen/Qwen3.5-4B` 原始权重，资格尚待真实运行；RTX 5090 工作站为主实验平台，承担 Agent 推理、数据生成、周期训练、恢复与集中评价。笔记本可继续日常开发与数据整理，最终模型部署验收后移到阶段 D。当前工作站实测为 WSL2、RTX 5090 D（32607 MiB 显存）、约 93 GiB 系统内存；运行记录保存当次实际可用资源。模型资格必须包含 128K+ 实际填充、长上下文信息定位、原生工具调用与多轮状态保持，8K/16K 只作接口诊断。`MiniCPM5-2B` 是条件性的跨模型验证候选，`Qwen3.5-9B` 是冻结能力参照候选，均不要求首阶段完整复现实验矩阵。momo-code 为优先核查的 Agent 运行基础，llama.cpp 为笔记本推理后端候选。Pi 仅在 momo-code 的本地接入、执行成本或可控性不满足需求时作为替代，不并行维护两套 Agent。训练由独立本地 Transformers/PEFT 或 Unsloth 组件承担；Harbor 的任务格式、运行器和检查器为评价复用候选。最终选型通过固定版本源码审查及真实加载、调用、梯度更新与导出验证确定，资格审查依据见[证据审查](04_证据审查与修订依据_v0.4.md)。

参数更新是待检验的研究手段。若明确作用域的外部状态已达到目标，或微调不能在未见任务上增益，应形成相应负结果；不能以继续增加复杂训练来维持“协同进化”叙述。

来源保持、记忆撤回、参数记忆与 Agent—模型联合优化已有直接研究。本项目不以这些概念的组合宣称首创。拟检验的贡献是：**来源与作用条件约束是否改善训练数据选择，以及这种改善能否在双机约束下转化为独立、跨来源、跨周期的参数收益**。创新性最终取决于结果和与最接近工作的实证差异，详见[证据审查](04_证据审查与修订依据_v0.4.md)。

## 2. 因素分解与可检验假设

设 `K` 为指令来源、作用域及生命周期控制；`R` 为跨任务经验检索；`W` 为模型权重；`S` 为训练候选选择。工具授权、任务环境和检查器构成各组共享的执行条件。

改变 `K` 不应同时升级经验库或权重；改变 `R` 不应引入额外任务事实；改变 `W` 时固定 Agent 和经验可见性；改变 `S` 时使用相同候选池和配额。较复杂策略多用的判定调用、提示 token、人工复核及失败重试全部计入成本。

| 假设 | 决定性比较 | 结论边界 |
|---|---|---|
| H1：显式生命周期有必要 | 简单来源/任务规则 `K0` 对比条件化生命周期 `K1`，固定 `R0/W0` | 行为越界减少，有效要求遗漏与任务完成不劣；仅控制器标签变好不足以支持结论 |
| H2：经验可以有选择地迁移 | 无经验 `R0`、普通 RAG `R1`、带适用条件与证据的检索 `R2`，固定 `K*/W0` | 在可复用任务上受益，在无关或条件反转任务上不过度沿用；不归因为参数学习 |
| H3：训练选择优于普通 SFT | 分层随机选样 `T1` 对比证据/适用性选择 `T2`，相同合法候选池与训练配额 | 独立未见 ETS 改善或旧能力损失减小；不能依靠更简单的任务构成解释 |
| H4：参数更新与控制策略兼容 | `K0/K1 × W0/W*`，关闭经验检索 | 识别权重收益及控制—权重交互；交互可为零或负，不要求“协同”必须超加和 |
| H5：更新模型改善下一轮选样 | 冻结模型选择器 `SF` 对比当前模型选择器 `SU`，共享逐周期候选池 | 长期收益可能来自模型→选样→模型的反馈；若仅闭环总收益成立，不夸大每一环的归因 |

正确完成率与错误率一起报告。拒答、询问、授权等待和无进展重复检查也属于行为结果；降低行动次数不能替代正确决策。

## 3. 任务与数据设计

使用可复位、可检查最终状态的多轮 episode。首批任务集中在与候选 Agent 相匹配的代码、文件和终端操作，优先复用 Harbor 格式的既有任务、环境与真实检查器，再增加跨会话指令变化和经验关系脚本。结构化文件处理、数据库查询与更新、受控本地文件编辑、离线 API 记录操作、代码/数值计算、证据检索与结果核验保留为后续扩展任务族，不作为首条闭环的六族覆盖要求。首批结果的能力范围限于已评价领域。正常任务包含合法写操作、任务续接和失败恢复，边界任务穿插其中，避免把全部研究缩成拒绝行动测试。

任务流具有三种预先标注的关系：**可复用**（旧策略适用于新任务）、**独立**（没有必要沿用旧经验）、**条件反转**（表面相似但适用条件或指令已变化）。撤回、休眠恢复、局部替代、摘要转述和工具结果中的伪指令在首批领域内覆盖，后续扩展到其它任务族。用户反馈由预定义事件脚本和真实工具结果驱动，各组获得等价反馈机会；自然用户试用作为后续外部验证，不用于替代控制实验。

episode 的事实来源、有效指令、工具 schema、允许行为、最终状态谓词和失败注入位置均可追溯。标注允许等效路径；检查器核验最终环境及所需报告，避免只认唯一工具序列。任务答案和检查器实现不得被待评估 Agent 当作工作文件访问。

数据分为学习流 `L`、开发集 `D`、选择集 `V`、发布回归集 `G`、封存确认集 `H`。原始纠错、任务实例及其改写/摘要/增强在来源簇内归属同一集合；另设任务结构留出，防止仅换文件名、工具名或数值被当作跨任务泛化。精确划分见[评估协议](02_评估与统计协议_v0.4.md)。

参数学习针对相对稳定的行为能力，如工具参数语义、缺参询问、引用实际结果和可恢复失败。项目路径、当前账户、临时偏好、授权状态、易变事实保留在外部状态，不把它们固化为无条件权重偏好。

## 4. 分阶段实验

实施阶段 A–D 是当前执行顺序，E0/E1/ER/ET/EC/EL 保留为科学实验编号。先形成工作站真实学习闭环与至少三周期稳定运行，再开展笔记本最终验收；K/R/W/S 对照贯穿工作站研究，不单独设为延后实施的额外阶段。

| 实施阶段 | 当前工作 | 完成依据与结论边界 |
|---|---|---|
| A：工作站环境与底座资格 | 在 5090 拉取固定版本 momo-code、Qwen3.5-4B 原始权重及 RSIGym 参考源码，安装实际兼容的推理环境 | 原生工具调用、128K+ 实际填充与信息定位、多轮状态保持；8K/16K 不替代资格验收 |
| B：真实学习闭环 | 修订 momo-code 模拟训练和评价路径，连接独立本地 LoRA、真实结果检查、训练准入和 Adapter 版本管理 | 真实梯度与参数变化、重新加载、真实评价及保持/回滚上一版本；不要求能力提升 |
| C：工作站稳定 RSI | 至少三个连续学习周期，处理新交互、候选数据、触发或拒绝更新、版本保持和中断恢复；每周期评价新任务及旧能力 | 稳定运行与持续能力收益分别判断，负结果和未更新周期完整保留；机制收益用 K/R/W/S 独立对照识别 |
| D：笔记本最终验证 | 将通过工作站研究与回归的接受模型合并、导出 GGUF、量化并部署笔记本 | 128K+ 实际上下文、Agent 工具行为、时延、内存、更新回滚；下降分解为权重、量化及后端影响 |

A/B 使用 L/D 中已授权、可核验的研究数据，不读取 H。C 的逐周期新任务与旧能力反馈来自允许的学习流或 D/V/G，不冒充封存确认结果；EL 的 H_cycle 仍在整条学习流结束后批量评价。机制比较固定运行基础与相应经验可见性；闭环候选不能无记录替代原始 W0。正式科学结论按独立冻结对照形成。

### E0：工作站执行与真实学习资格，部署后移

取消笔记本优先的 CPU/Q8/8K E0。先在 5090 原始权重和高精度推理环境上接入 momo-code，检查原始生成、原生工具调用、解析、真实执行、返回及最终状态。8K/16K 可用于定位接口故障，但通过短上下文不等于模型资格通过。

资格要求实际送入至少 131072 个输入 token（128K），另留生成和多轮续接空间；计数依据模型 tokenizer 与后端实际 usage，不以字符数、配置上限或自动压缩前的历史长度代替。保存前/中/后位置的信息定位结果、长上下文下的工具语义及跨轮状态保持，记录截断、压缩、资源与耗时。若发生自动截断或摘要压缩导致实际输入不足，长上下文资格未通过；失败原因据实记录，不降格为短上下文验收。

首条闭环使用足以核验接口的小批真实任务，不先制作全套评价底座；随后机制试点仍以 36 来源簇、每簇 2 episode 为建议起点。完成一次真实 BF16 LoRA、Adapter 重新加载及工作站评价，再进入至少三周期 RSI。Adapter 合并、GGUF 导出和笔记本回归安排在 D，不阻塞 B/C。

### E1：指令生命周期，固定模型且无经验检索

主要比较 `K0` 与 `K1`。`K0` 保留来源标识、显式任务/项目匹配、最新直接要求和撤回标记；`K1` 进一步表达条件生效、休眠恢复、局部替代和派生链撤回。两组共享实际工具权限与当前用户输入。无历史和原始历史只作诊断参照，不替代强简单基线。

主要观察行为 FAR，联合检查 FDeR、ETS 和已授权任务的完成覆盖度。另报告控制器集合错误，以区分“选错要求”和“要求已正确提供但模型执行错误”。模型辅助歧义判定只在规则的剩余错误有足够价值时增加；人工给出的正确有效集合仅用于诊断上界。

### ER：经验检索，与指令控制分开

固定 E1 选定的 `K*` 和初始 `W0`，比较 `R0/R1/R2`。经验库全部来自允许使用的学习流，三组当前事实、工具与总体上下文上限相同。`R1/R2` 使用同一历史候选库和检索 token 上限；R2 增加条件/证据筛选，实际用量及筛选成本保留。

分别测可复用、独立、条件反转任务；可加无关经验对照判断检索噪声。有效历史指令由 K 提供，经验对象由 R 提供，禁止以经验形式绕过指令生命周期。此实验完成即可形成外部经验学习结论，不依赖微调成功。

### ET：参数学习与候选选择

所有主比较从同一 `W0` 开始，固定 `K*`、工具和训练配置。相同来源/任务层的合法候选池提前形成，训练配额按任务族、轨迹深度、目标动作类型和来源簇冻结。已知错误行动不作为正向目标。

| 组 | 数据策略 | 比较解释 |
|---|---|---|
| T0 | 冻结 `W0` | 参数学习零更新参照 |
| T1 | 全组共享的授权与标签检查后，来源去重、分层随机抽取核实成功轨迹 | 强普通 SFT 基线；“无筛选”特指无研究性的效用/作用条件选择 |
| T2 | 同一成功候选池与相同分层配额，按证据完整度、适用条件和可迁移效用选样 | `T2−T1` 检验选择策略，而非任务组成或重复来源的变化 |
| T3 | 成功样本加学生失败状态的局部正确续接、缺参询问、不调用和恢复样本 | 检验纠错数据配方的净效果；与 T2 的差异不能单独归因为某一种边界标签 |

T3 的纠错动作必须在学生实际前缀状态重新执行，并生成真实后续结果；只修改一条调用而保留旧后续工具结果不构成正确轨迹。监督仅施加于核实的正确 Assistant 目标，失败动作和工具观测作为条件信息使用。若要证明局部纠错优于完整轨迹重建，另做相同失败 episode 的匹配比较；不从 T3−T2 直接推得。

主分析统一**监督 token 预算、优化器、有效批量和序列长度处理规则**，按目标及前缀长度匹配主选择比较；实际步数、上下文 token 与 GPU 时间单列，不能假定这些预算也同时相同。必要时对决定性比较追加等 GPU 时间结果；不全面翻倍全部矩阵。筛选、生成、修复、人工复核、训练和推理的总成本单列，避免把数据质量收益写成免费效率收益。

初始主训练三组各 3 个随机种子；若预算不足，先完成 T1/T2，T3 标明探索性。候选选择只用 V。独立权重评价关闭经验检索，使用相同事实、K 与高精度推理配置；部署量化结果另报。仅部署后提高而高精度权重不提高时，不能直接归因于参数能力。

### EC：兼容性及真实性

以已选定 W* 完成 `K0/K1 × W0/W*`，经验关闭，四组运行相同 episode。报告各单元 ETS 与跨任务错误，估计交互，允许控制收益与权重收益相加、替代或冲突。然后在部署候选上补测 R2，识别权重在已有经验检索之上的增量价值。

同时对固定检查与输出呈现，分别保存模型原始声明、工具实际状态和最终展示文本。外部检查器阻止了错误完成宣告，不能计作模型自身减少幻觉。BF16、合并权重、Q8 与条件性的更低量化采用同任务配对；模板/parser 保持冻结，必要修复对受影响基线和候选一起复测。

### EL：三周期机制试验，随后才考虑真实闭环

首个纵向试验采用三周期共享候选池 `P1/P2/P3`，固定 K*、检索策略及工具。所有组在每周期看到同一批来源任务、候选格式与检查证据；可混入固定 W0 和当期模型按平衡配额生成的轨迹，组成规则事前确定。主比较为：

- `SF`：始终用冻结 W0 辅助选择；`SU`：用该组上一周期已接受模型辅助选择。选择提示、候选调用数、生成 token 上限、分层配额及独立核验一致。
- 两组每周期从各自已接受 Adapter 续训，使用相同更新预算与固定 replay 配额；不训练时记录原因为“无需更新/候选不足/回归/运行失败”，保持上一版本。
- 学习流的前瞻结果与旧能力 G 每周期记录；`H_cycle_1/2/3` 周期确认面板只在整条试验完成后批量评分，其反馈不用于后续选样、训练或发布。

共享池试验先回答模型辅助选样的贡献。若各组各自生成任务、发现失败并筛选再训练，数据分布同时变化，只能估计完整闭环收益，不能沿用共享池的归因。

更新触发与发布阈值对两组相同、事前冻结，选择器不能自行修改。未用完的周期额度不向某组额外任务重分配；报告共同额度与实际消耗，并展示性能随累计成本的关系。所有流都进入终点比较，不能只保留接受更新的周期或只完成的运行。

在一个预先指定周期做交叉重训诊断：两组选择的数据从同一周期前 checkpoint 出发，各训练一次，直接检查选样差异是否改变下一步收益。该诊断仍有训练随机性，不替代主重复试验。

初次 EL 运行两条独立学习流，作为纵向可行性和机制证据；若要形成稳健持续收益结论，再扩大到至少三条独立流并按评估协议规划规模。三周期只覆盖短期积累，不能证明长期收敛。真实人机交互闭环、DPO/RL、多个 Adapter 或结构更新属于后续扩展，不预设必须开展。

## 5. 推进、发布与停止

当前实施顺序为 A → B → C → D：工作站资格、真实学习闭环、至少三周期工作站 RSI、笔记本最终验收。E1/ER/ET/EC 的对照在工作站形成，EL 保留共享池选样与延迟封存反馈。第一条闭环不以全套正式评价底座建成为前置条件，但训练前仍须满足来源、授权、正确目标和 loss mask 契约。E1/ER 不必等待 ET 有正结果。若单轮 ET 无增益，但错误集中于可纠正的状态失配，可在预算内开展一次有明确假设的纵向试点；不能无限重复微调。

项目内部操作遵循一次能力授权后持续执行：允许的工作目录内读写、离线计算、可恢复编辑和 fixture 更新无需逐次确认。撤回和明确禁止立即生效；超出范围、外部不可逆副作用或确实缺失关键授权时才单独处理。研究中记录不必要确认、重复检查和授权等待，避免以低行动率取得表面可靠性。

正式推断与部署发布是两种判断。回归集可反复用于发布选择，因此属于自适应选择信息；封存集只支撑未参与选择的确认结论。训练 loss 下降和权重变化证明更新发生，不能证明更新有用；未通过部署回归的模型仍可保留为实验候选并报告其科学结果。

当前总资源上限与具体运行配置见[双机协议](03_双机运行与训练协议_v0.4.md)。若样本量、种子或周期在上限内不足，减少研究分支并明确结论精度，保持正常实验运行。结果允许为：外部状态有效、检索有效但权重无增益、权重有效但两者无正交互、筛选不优于简单规则，或出现需要解释的负迁移。
