# CoEvo 实施与复现：PilotDeck 复用与 RSI 学习闭环

科学定位见[研究方案](研究方案.md)，结果归因见[评价与统计](评估与统计.md)。**PilotDeck 的源码运行环境和本地模型配置已就绪，完整任务接入正在验证。** 具体实现与实际结果见 [接入记录](../experiments/pilotdeck/README.md)。以下区分已有上游能力、当前接点与后续研究路线。

## PilotDeck 能直接提供什么？

本轮固定阅读 [OpenBMB/PilotDeck main@783499ff](https://github.com/OpenBMB/PilotDeck/tree/783499ffdb2d501bf590b2e035acd027a882df10)。已看到 AgentLoop/AgentSession、工具与权限、Workspace、原生会话 Transcript、上下文恢复/压缩、文件检查点、MCP/扩展、记忆提供器、Office Skills、桌面与后台工作代码。这些功能原则上由 PilotDeck 承担，CoEvo 不再发展功能重复的桌面框架、通用 Agent Loop、Office 编辑器或任务平台。其 Skills 在 Word/表格/PPT 修改中要求保留未请求改变的内容，并提供选择性的验证、渲染与交付工具；这些只支持技术处理，不替代模型的事实判断。

**已核实的接入能力**：项目/用户插件清单可声明 Skills、commands、Hooks 与 mcpServers；源码中的 PluginRuntime 和 products/_example 示例确证这种形式。生命周期事件含 PostToolUse、PostToolUseFailure、SessionStart/End、Pre/PostCompact；可通过 command 或 HTTP hook 使用外部程序。FileChanged 目前只有 TODO 声明，**不能假设已被调用**。原生 AgentTranscriptEntry、TranscriptWriter 表示用户输入、消息及工具结果、轮次、工件、压缩/恢复边界，可作为长期经历数据来源，但完整可回放的外部提取仍需要实际实现/确认。

MemoryResolver 已提供 retrieve/captureTurn 抽象，EdgeClawMemoryProvider 提供已有实现。**磁盘安装的 JSON 插件不能自动注入任意 TypeScript 内部函数**；源码说明程序化 prompt/router contribution 目前仅供内置或测试注入插件。因此先使用真实可用的 Skill/MCP/Hook 与外部训练程序，只有存在真实能力需求时，才在上游清晰扩展点补足策略接入；不声称记忆策略替换已经实现。

PilotDeck 项目采用 AGPL-3.0。个人本地研究、复制、分发、修改版网络服务的实际许可证义务应依具体行为处理；用外部插件或进程隔离**不能当然推定**规避上游许可。固定来源版本、保留著作权与许可信息，优先通过上游贡献减轻长期私有分叉。其宣传的 WorkBuddy Bench 79.1/2000 条交互压力测试，本轮缺少公开任务级/恢复记录，不能作为选型确认事实。

## 保留 CoEvo 哪些能力？

保留 src/coevo 已具备的真实来源标注、轨迹/有效行为提取、监督目标组织、Transformers/PEFT BF16 LoRA 更新、Adapter 回载、评价与科研记录；不为 PilotDeck 新写 Python 训练底层。当前 Qwen3.5-4B W0 的 Pi/vLLM 原生 thinking、工具、LoRA 已实测，Spark-X2.5-4B 仍是候选。原 Pi complete_work/MCM/历史运行入口保留复现用途，**待 PilotDeck 真实接管日常任务后**，再决定删减旧通用执行路径；不继续并行开发两个生产 Harness。

集成应是一条有实际结果的闭环：

1. 使用 PilotDeck 原生 Workspace/Office Skills/模型工具处理获授权的真实工作，形成工件、Transcript 与实际用户反馈。
2. 通过现有 Transcript 和生命周期 Hooks 取得必要的任务事实、文件版本与反馈，在 CoEvo 侧保留来源、操作者、辅助介入和可验证的部分成功/失败。
3. 根据现实需要由 Agent 提出条件经验、Skill/Harness 修改或参数训练候选。CoEvo 现有 Python 工具处理合法训练目标；错误推断、未核实结果、教师代写不自动作为自主正确监督。
4. 将选中的经验/Skills/Harness 配置或经训练的新模型，通过 PilotDeck 已支持的接口及本地 vLLM 模型服务用于下一次真实任务，再依据成果与成本决定继续、撤回或调整。**需要实测确认** vLLM OpenAI 兼容流与 PilotDeck 模型提供器、reasoning/tool parser 的确配合，而不是看到“模型无关”就认定 4B 长程工作可用。
5. 在未来不同来源任务中研究是基础 Harness 改善、即时纠错、R/K 收益、W_task 学习还是 W_evolver/S 改进策略获得收益，不让研究者代劳或模型路由污染归因。

这条链路可以利用现有文件和 HTTP/插件扩展；不先开发另一套通用事件总线、记忆数据库、桌面 UI、模型集群或自动评分平台。PilotDeck 的文件检查点存在目录、大小与后台写入边界，不能把它当成所有外部副作用可无损回滚。

## 实际推进取舍

优先让 PilotDeck 完成用户确实需要的已有 DOCX/XLSX/PPTX 文件维护、文献资料更新与长期项目任务；关注源文件保真、必要事实和计算、用户返工。模型选型（Qwen W0 或 Spark 等候选）须考虑单 RTX 5090 D 32GiB、约 96GB RAM 的推理/训练条件，以及实际任务质量，32GB 无独显笔记本未验收。生产用途可以选择多模型支持，科学 RSI 对照必须记录或固定参考模型的介入。

随后优先从实际任务反馈中研究外部经验与参数学习；对 Harness/Skills 的自主改进只有在后续成果得到支持时保留。待产生真实有效的多轮改进经历后，研究训练 W_evolver、选择器与下一轮改进能力。它们是科研优先级，不是串联审批门禁。真实负结果应触发路线缩减，而非继续打补丁和添加格式检查。

只在 main 开发与同步；现役职责文件仅为研究、评价、实施三份，实验实测保留在 experiments 和 Git 历史。正常 Python CPU 检查仍可用：`PYTHONPATH=src python -m unittest discover -s tests -v`，Pi 语法检查 `node --check scripts/pi-project-agent.mjs`。仅在技术改动实际影响这些路径时使用，不用测试覆盖量衡量研究进展。
