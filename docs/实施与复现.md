# CoEvo 实施与复现：真实长期工作驱动

现行职责：科学设计见[研究方案](研究方案.md)，结论如何成立见[评估与统计](评估与统计.md)，首个综合工作任务见[2025 MCM C](../experiments/mcm-2025-c/README.md)。本文件只规定现有技术路径、数据语义、模型替换边界和持续开发原则。当前正常在 `main` 开发；接受权重仍是 Qwen3.5-4B W0，Spark 仅为候选，MCM首次W0及原生纠错续接已结束，未形成建模工件或证实有效恢复；用户授权中途输出8K→16K调整已单列记录，入口、环境与实测见任务记录。

## 现有能力与缺口

已实测 Pi SDK/momo-code 的真实工具执行、会话 fork/续接、轨迹与状态采集、纠错讨论、基于核验行为的监督目标、BF16 LoRA 更新、独立加载 Adapter 和开发任务复测。工程测试通过不是长期能力证据。当前 `rsi.py` 是有界三周期试点，尚无跨多个完整真实工作流的自动持续学习收益。具体历史见[实验结果](../experiments/real-work-foundation/stage-update-2026-10-14.md)。

目前主要可用模块：`scripts/pi-project-agent.mjs` 和 `src/coevo/project.py/everyday.py` 执行；`extract.py/behavior.py/workflows.py` 处理可见交互及目标核验；`native_learning.py/memory.py` 研究会话与外部经验；`supervision.py/train.py` 组织监督及 LoRA；`evaluate.py/state.py/rsi.py` 提供开发评估和版本/周期记录。历史试点模块保留作结果复现，不应自动当成新任务的并行架构。

## 综合工作任务的执行合同

MCM 官方赛题的原始 PDF 和五份 CSV 由来源清单绑定 URL、取回时间和校验哈希，未经下载核实前不声称数据已经在仓库可用。准备独立的 Agent 工作区与评价区；研究者控制题面、数据可见范围、任务交付和反馈时间。Agent 可以自主建模、写脚本、测试、回读文件、修改方案和形成报告；不为每一步人为审批。只有超出明确授权的读写、外部数据使用和训练用途需另行授权。

工作产物建议落在任务专属目录：`data/`（提供的官方数据与版本）、`src/`（模型与图表程序）、`outputs/`（预测表、图、回测、区间）、`report/`（完整论证与复现说明），这些是交付类别而非强制脚手架。评价检查器在独立路径使用不可写的真值与测试，不让模型读取后自行优化。回测必须先构造按预测时间冻结的数据快照；不把未来官方数据列名、队伍别名或比赛项目计划意外带回历史。公开题面中的 2024 结果不可能构成盲测 H。

保留工作流唯一来源 ID、每次运行的模型身份、原始任务/有效指令、可见消息/工具 schema、完整可见动作及返回、文件变更、用户反馈、分支关系、环境和配置、每次阶段成果与评价。超时后仍有有效工件可评分，检查器异常与实质任务失败分开。只记录可见内容，不导出不可见模型内部推理。可训练目标需要对应实际可验证的正确行为，完整失败轨迹可以用于诊断而不能自动转成正样本；研究者/教师辅助不算模型独立成功。

## 底座决策和训练

工作站 RTX 5090 D 32 GiB 显存、主机约 96 GB 内存；笔记本 32 GB 无独显，最终部署未完成。现有模型路径、工具解析、thinking 和训练加载与 Qwen3.5-4B 绑定，例如 `configs/workstation.json` 使用 `qwen3_coder` 解析器，`train.py` 使用 Qwen 对应的 Transformers 类与模板。替换为 [Spark-X2.5-4B](https://huggingface.co/XHToken/Spark-X2.5-4B) 不能简单改模型路径，需要核对官方权重修订、许可证、Tokenizer/chat template、工具流格式、推理服务支持、训练类、LoRA target modules、Adapter 独立回载、显存/吞吐及许可证约束。

先确认**完整任务行为、资源开销及工具有效性**，再判断谁作为单一纵向主底座。保持同题、同工作区、可比调用/时间/资源和各自正确模板，单独说明 thinking mode；不把公开榜单当成实测。不同架构必须分别建立 W0→W1 权重谱系和对应数据曝光。基础模型如果无法正确完成任何有效工作，允许先改善 Agent 交互提示和工具接口，但不能把这些工程变化冒充参数学习收益。

当前训练机制沿用 Transformers/PEFT BF16 LoRA 和真实核验目标；尝试 SFT 后分别测试新增技能、旧技能、外部 R 打开/关闭与成本。当高质量长期轨迹已形成时可研究 [QwenGyre](https://arxiv.org/abs/2609.33848) 提倡的前缀共享、分支去重和部分成果评分；它不表示 CoEvo 已具备该论文的训练器。单卡无需复制多节点弹性调度，RL 需在任务级奖励可靠后再决定。

## 开发与证据维护

只保留 `main`，直接提交和同步 GitHub，不默认建 PR 或日期版规范。开发日志归 `experiments/<study>/`，`docs/` 仅维护现行三份职责文档。首次 MCM 任务设计归 `experiments/mcm-2025-c/README.md`，其后真实运行结果独立建产物，不在方案里追加流水账。正式对照要保留冻结来源、样本边界、提示、代码、数据与模型版本、成本和失败；不要求每个局部工具动作都另建实验。

保留合适的单元与关键集成检查：`PYTHONPATH=src python -m unittest discover -s tests -v`；`node --check scripts/pi-project-agent.mjs`。CPU CI 可能跳过需要 GPU/Pi/私有工作区的测试。授权执行任务、存储经历和把经历用于训练是三种不同许可；私人材料、凭据与权重不推入公共 Git。实验确认和模型晋升不能仅基于 D/G 的局部改善。
