# CoEvo 实施与复现：面向真实工作与学习的技术边界

科学问题与阶段判断见[研究方案](研究方案.md)，有效证据见[评估与统计](评估与统计.md)。本文件记录现役技术路径、真实执行的职责及边界，不承载逐次实验流水账。当前在 main 开发；用户没有因此授权启动任何新的 GPU 推理、训练、底座替换或自动 RSI 周期。

## 现有可用能力

当前接受底座是 Qwen3.5-4B BF16 W0，Spark-X2.5-4B 未完成实际接入或公平对照。RTX 5090 D 32GiB 与约 96GB RAM 的工作站已经跑通 vLLM、Pi 原生 read/write/bash、原生会话续接、thinking 字段/工具往返，以及 Transformers/PEFT BF16 LoRA 训练和 Adapter 独立回载。32GB 无独显笔记本的最终部署没有验收；131072-token 长输入资格成功不等于长程工作能力。真实运行与完整私人轨迹在本地，公开 GitHub 只保留源码、协议及受控摘要。

继续复用既有职责：scripts/pi-project-agent.mjs 负责任务 Agent 的工具、消息与执行记录；src/coevo 下的工作流/经历模块负责真实轨迹、经验及训练目标；train.py 与模型服务负责候选参数更新、载入；state.py/evaluate.py/rsi.py 提供必要的状态与运行支持。历史小任务 Pilot 保留证据复现价值，不自动成为新科研工作流的并行平台。

**已解决的技术问题不再反复立项**：Qwen thinking → Pi reasoning → read/write/bash 真实执行已验证。MCM 原生 thinking 恢复运行也已经产生源码；其科学无效和独立复跑失败属于工作能力观察，不是尚未打通 thinking 的接口故障。结束状态应区分进程退出、实际工具/模型停止原因及工件质量；CI 只支持其运行的检查，不代表 GPU 或科学确认。

## 完整任务的执行方式

由真实需求选择工作：实际软件仓库修改、科研数据/建模、跨会话持续工作等。给模型合法数据、工具与任务目标，让它自主决定方法、执行、修改和提交可用成果。现有 Pi 执行器提供边界，不围绕每一步动作建立新的审核器或专用状态平台。研究者或高能力参考 Agent 可以提供可识别的外部反馈；模型独立工作与辅助成果不混淆。

每个工作流至少能追溯：任务与来源、当时有效约束、输入数据与环境、模型及 Harness 版本、实际动作与返回、可见反馈、工件变更、资源消耗、最终成果和重要失败。可按实际需要保存完整原生会话及文件快照，避免消息分叉后工作区文件状态不对应。原始证据可以长期保存，给模型的可用经验则根据实际帮助和适用条件选择；不预设必须由多层记忆数据库、固定 Schema 或压缩代理实现。

对训练目标与经验提取，不要求整条任务完全成功：已核实的部分工作、反馈后的有效修订和真实失败上下文都具有研究价值。但必须分清哪些行为正确、谁提供了答案、哪些只是检查器阻止的失败；不能将未验证的拟合、未来信息泄漏、教师直接给出的代码或 Agent 自称完成自动当作自主正确监督。原始轨迹与可训练目标分开保留。合法任务使用不自动授权永久记忆、训练或公开数据。

若任务涉及科学预测，应按预测时点定义可见数据并独立保留评价材料。MCM 公开资料和 2024 既有真值不是盲测；官方 CSV 的回顾性版本也不能当作有历史发布日期的原始时间快照。沿用[现有 MCM 任务入口](../experiments/mcm-2025-c/README.md)作为开发案例，原始运行数据与已发表摘要不因新方案而重写。

## 底座、学习与自我改进的实现决策

底座选择先比较代表性完整工作的成果和成本。Qwen W0 的真实历史保持不变；若采用 Spark 候选，应验证其官方模型修订、许可证、Tokenizer/chat template、reasoning/tool parser、模型服务、LoRA 可训练模块、Adapter 重新加载与显存/吞吐。Spark 官方建议的思考采样与 Qwen 不同，需各自正确配置并记录比较条件；不得把迁移适配成功解释为能力增益。单卡算力是重要约束，选择适合纵向研究的可训练主模型，不长期维持无必要的双底座平台。

已有 BF16 LoRA 可用于真实工作经历的学习研究。候选训练从有依据的有效行为或纠正经历中产生，不因训练工单能运行就直接启动或晋升。Q1 的外部经历、Q2 的 W_task、Q3 的 Harness 与 W_evolver 可以根据实际工作提供的数据并行探索。对于某种机制的收益，需要使用相称任务/资源并在后续工作核实，避免为了完成预设矩阵制造无意义任务。

Harness 允许改进通用提示、工具组织、上下文与错误反馈的工作方式，以及必要的恢复逻辑；允许 Agent 自己提出并试行改进。权限、来源、原始证据和独立评分器不是可搜索对象。应复用现有 Pi 功能与 Git 版本恢复，而不是先复制 Evo² 的整棵搜索树、双角色 GRPO 或 RSIGym 的远程服务集群。若某类真实工作反复暴露系统性运行瓶颈，可以整体修改执行逻辑；不能为局部异常反复堆叠保护和兼容层。

Pi SDK 版本与当前实验谱系分别记录。此前对比已发现 Pi 1.1.0 本就具有 agent_settled.aborted，且 Bash 失败返回语义不因 1.2.0 而出现新能力；不因新版本存在就追溯改变既有运行。需要上游修复或新功能时再升级，并针对实际受影响的工作路径检查兼容性。

## 开发维护与复现

保持单 main 开发、直接提交和同步；不默认建立 PR/审批制度。docs 下只维护现行研究方案、评价与实施说明；实验实际事实、负结果及来源清单留在 experiments，历史通过 Git 追溯。新增复杂性应直接对应工作瓶颈或科学假设；审查重复流程与过时补丁，删除前确认实际依赖和保留必要证据。

需要时复用现有 CPU 回归入口：`PYTHONPATH=src python -m unittest discover -s tests -v`；Pi 适配器语法：`node --check scripts/pi-project-agent.mjs`。它们属于一般工程维护，不是完整任务能力或协同进化的科学证据。只有用户明确授权，才执行新的模型推理、训练、RSI 周期或模型替换；任何自动化改动不得扩大权限或读取独立评价真值。
