# 运行与训练约束

底座为 **Qwen/Qwen3.5-4B**，执行与训练分别复用 Pi SDK/momo-code、vLLM、Transformers/PEFT。

工作站 RTX 5090 D（约 32 GiB 显存、约 96 GB 内存）负责主要训练、集中评价；32GB 内存、无独显的笔记本承担日常开发与后期部署验收。历史试跑环境为 vLLM 0.31.0、Transformers 5.17.0、PEFT 0.21.2、BF16 LoRA。已实测一次 **131072 输入 token** 的前中后定位及工具/多轮状态，约 50.29 秒；该结果用于资格判断；实际长上下文任务能力另行评估。训练样本无需达到该序列长度。

仓库 `tasks.py` 保留简单合成文件任务，`project.py` 和 Pi 薄适配已在独立 Marko 副本实测受控 read/write/bash、会话 fork 和独立检查；这些 D 任务未形成训练候选。`extract.py` 已能记录和导出工具轨迹，`state.py` 有版本/经验状态，`train.py` 可真实 LoRA 训练，`rsi.py` 有暂停中的试点周期。当前 `train.py` 仅监督经过核验的 write 动作，缺完整的读、执行、观察、纠错、询问和停止行为训练。一次 6 步、327 监督 token 的候选旧任务 3/3→0/3；CPU 复核确认六条目标的模板前缀对齐，仍全部只监督 write；这支持优先检查监督覆盖，但没有定位退化原因，见[诊断记录](../experiments/project-tasks/lora_diagnosis.json)。

应首先核对训练和推理 chat template/tool schema、监督 mask、Adapter 加载与优化设置，再使用真实日常任务的完整正确 Assistant 行为作为 SFT 监督。SRFT 采用更新前冻结 checkpoint 在独立通用任务上生成、筛选 replay；作者 Counting 任务 Task:Replay=4:1 是样本数比例，80%–99% 的能力下降缓解只属于作者技术报告设定。需记录实际监督 token、回放来源、生成筛选和训练成本；跨周期 Wt replay 可能重复旧错误，保留 W0 基础参照。

训练触发目前停在 `training-request.json` 和人工调用，后续训练触发方式与版本发布策略在真实长期学习阶段确定。版本更新需依据 G 回归接受或撤回，H 用于独立科学确认。当前没有运行中的训练或周期实验；本次方案合并不触发推理、训练或版本晋升。
