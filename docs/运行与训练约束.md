# 运行与训练约束

唯一底座为 **Qwen/Qwen3.5-4B**，不再考虑其他底座竞赛或引入内置高级 Agent。继续复用现有 Pi SDK/momo-code、vLLM、Transformers/PEFT，避免另建执行框架。

工作站 RTX 5090 D（约 32 GiB 显存、约 96 GB 内存）负责主要训练、集中评价；32GB 内存、无独显的笔记本承担日常开发与后期部署验收。历史试跑环境为 vLLM 0.31.0、Transformers 5.17.0、PEFT 0.21.2、BF16 LoRA。已实测一次 **131072 输入 token** 的前中后定位及工具/多轮状态，约 50.29 秒；只是资格测试，不能说明所有长上下文日常任务可靠。训练样本无需达到该序列长度。

仓库 `tasks.py` 仅有简单合成文件任务，`extract.py` 已能记录和导出工具轨迹，`state.py` 有版本/经验状态，`train.py` 可真实 LoRA 训练，`rsi.py` 有暂停中的试点周期。当前 `train.py` 仅监督经过核验的 write 动作，缺完整的读、执行、观察、纠错、询问和停止行为训练。一次 6 步、327 监督 token 的候选旧任务 3/3→0/3；不可未经诊断解释为灾难性遗忘。

应首先核对训练和推理 chat template/tool schema、监督 mask、Adapter 加载与优化设置，再使用真实日常任务的完整正确 Assistant 行为作为 SFT 监督。SRFT 采用更新前冻结 checkpoint 在独立通用任务上生成、筛选 replay；作者 Counting 任务 Task:Replay=4:1 是样本数比例，80%–99% 的能力下降缓解只属于原论文设定。需记录实际监督 token、回放来源、生成筛选和训练成本；跨周期 Wt replay 可能重复旧错误，保留 W0 基础参照。FINCH、SLoRA、RL 或模块路由只在观察到明确瓶颈时另作研究决定。

训练触发目前停在 `training-request.json` 和人工调用，这只是当前工程边界，不代表研究目标要求永久人工训练。版本更新需依据 G 回归接受或撤回，H 用于独立科学确认。**文档更新不授权恢复已暂停的训练或周期实验。**
