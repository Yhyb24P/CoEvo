# CoEvo 研究方案：真实工作驱动的 Agent—模型持续适应

**状态（2026-10-15）**：研究正常推进；仅使用 `main`。当前已接受底座为 `Qwen/Qwen3.5-4B` 的原始 W0，尚无已晋升学习权重。`Spark-X2.5-4B` 是优先评估的替换候选，不是已完成的底座迁移。2025 MCM C 已确立为**首个综合性长期工作任务候选**，首次W0及早期原生纠错续接已执行，行动有所改变，但未证实有效恢复或产生建模工件；尚未进行MCM参数学习，实测见[任务记录](../experiments/mcm-2025-c/README.md)。历史开发事实见[2026-10-14 阶段记录](../experiments/real-work-foundation/stage-update-2026-10-14.md)。

## 科学目标及可证伪的问题

在合理的资源、权限和任务机会下，小模型 Agent 能否从**完整真实工作经历**中获得未来任务的独立净收益？经历可在当前原生上下文中发挥作用，或被提炼为跨任务经验/Skill，或经训练改变模型参数。必须分清“这次依靠反馈完成”“新会话靠外部经历完成”和“关闭外部经历后模型仍能完成”。成功工作流、训练参数变化、生成笔记或训练运行次数，均不是持续进化的充分证据。

研究维度为 `K`（当前有效的指令及生命周期）、`R`（外部经历和条件化 Skill）、`𝓗`（Harness：提示/工具/上下文/反馈与执行控制）、`W_task`（任务执行模型参数）、`W_evolver`（提出和反思改进的策略参数）、`S`（训练来源与修改候选的选择）。它们是因果分析维度，不要求各建一套服务；可以由同一模型按不同角色工作。`H` 仍专指封存评价集，与 Harness `𝓗` 不混用。特别关注条件撤回、时间变化、未经验证的经验固化、错误完成宣称和旧能力遗忘。

- **Q1：何种经历、在何种条件下值得保存与复用？** 固定 W0，比对无历史、原生完整历史、可回放外部经历、自由提炼笔记和带作用边界的经验；同时观察信息遗漏、条件变更和撤回。允许结论是“保留原始历史比抽象 Skill 更可靠”。
- **Q2：什么行为值得写入权重？** 用合法且确有正确目标的经历训练 W1，在保持同一模型、工具、任务和来源基础上比较 `R0W0、R1W0、R0W1、R1W1`，计算迁移效果、负迁移、遗忘与资源成本。模型自审、成功轨迹和 Replay 不自动构成可信监督。
- **Q3：改进策略能否使下一轮学习更有效？** 一方面，更新后的任务模型是否更能提炼与选择可复用经历；另一方面，Proposer/Reflector 是否能提出、诊断和选择更有效的 Harness 修改。固定任务模型测试 Harness 的独立增益，训练进化策略后再检验是否比冻结策略更会改 Harness，并在独立任务流中评价长期净收益。两条线不得混同。不得把未晋升候选叫作正式 SU。

**反例同样有效**：较强的基础模型可能更少需要外部记忆；完整历史可能优于压缩经验；LoRA 可能局部有效却损害其他任务；选择器可能与随机策略无差异。出现这些结果时收缩机制，而不是追加防御性的审核/架构。

## 主任务生态：先完整工作，后机制对照

研究单元是具有实际成果的连续工作流：任务需求、可见指令与工具环境、模型可见消息、动作与返回、用户/研究者反馈、代码及数据状态变化、重试/分叉/压缩、部分成果、最终工件和独立检查。要求 Agent 真实执行，允许其选择方法、写代码、运行工具、复盘并修复，而不是将赛题拆为数十个静态问答。

**首个综合性研究任务是 [2025 MCM Problem C：奥运奖牌榜建模](../experiments/mcm-2025-c/README.md)**。COMAP 官方题面要求历史数据建模、2028 年金牌/总奖牌预测及区间、首获奖牌国家、项目设置、教练效应、原创洞见和论文式呈现。它适合观察完整数学建模与软件工作的协作。此任务**不改变 CoEvo 的一般研究对象**；后续必须引入不同领域和数据生成机制的独立工作任务，才能支持可泛化的结论。

当前先把它作为一条完整开发任务流，而不是独立 H。原因是赛题及 2024 年部分真值公开，既有解答也可能被模型见过。评价需要限制可见输入、回测时按预测时点冻结资料、保存真实计算与可核验产物；对 2028 的预测只能审查方法和合理性，**目前不能计算 2028 实际误差**。官方原题只允许所附数据参与模型和数据分析，外部资料只能作背景与解释。[官方赛题](https://www.contest.comap.org/undergraduate/contests/mcm/contests/2025/problems/2025_MCM_Problem_C.pdf)。

自然工作流的主要研究机会是：数据一致性与未来信息泄漏；数学假设和代码实现一致性；时间外推、预测区间与无奖牌国家；错误的工具处理和虚假完成；遇到更改预测时点、输入编码、数据修正、指标口径或撤回历史假设时，Agent 是否正确调整行为。不能把“教练效应”的相关性直接写成已识别的因果效应。

现有 Marko 软件开发、表格试跑和四族工作流继续作为历史证据/工程回归，不再是研究的默认数据生产模式。成熟后，以不同真实科研分析、工程与办公任务构造第二、第三类独立工作流；数学建模任务内部产生的分支、变体与历史回测仍继承对应原始来源簇。

## 研究推进与决定性证据

**阶段 A：综合工作能力与基座确认。** 首先核实 Qwen thinking 的模型模板、Pi 推理字段和工具调用实际生效，再对已有 MCM 错误检查点进行有界执行；确认基础配置的有效工作能力后，才在相同任务工件、授权环境及独立评价下比较当前 Qwen W0 与候选 Spark-X2.5-4B。各自使用正确原生工具模板、解析器及思考配置，公开报告真实可见信息、成功任务范围、时间/显存/调用消耗和部署故障。基座最终只选一个作为随后纵向实验的主模型；历史 Qwen W0 结果不被候选结果追溯重标。若 Spark 适配/训练不可用，应先区分工程不兼容与能力不足，而不是盲目替换模型。

**阶段 B：完整任务与 Q1。** 运行一条 MCM 工作流，保留首次尝试、有效工件、反馈后续接和复盘。让不带原会话的新执行分别使用无历史、完整经历和提炼经验处理新的有效任务，检验任务完成、过期经验误用及成本。更多不同结构任务用于检查外推。自由表达仍允许；只有执行和训练接口需要时再结构化。

**阶段 C：Q2。** 在确有可训练行为、且错误类型跨实例重复的情况下，对同来源集合从同一 W0 训练候选 W1；保留 R 开/关及旧任务回归，独立载入 Adapter。SFT/Replay/参数化遗忘仅在足够证据显示必要时比较，不能把所有纠错记录直接转成 loss。外部经验收益与参数收益分别报告。

**阶段 D：Q3 与 Harness 进化。** 可先在固定 W0 下考察可撤销 Harness 修改是否相对于相同配置下的普通反馈有实际增益；待有真实有效的修改轨迹、经过选择的 W1 与多个独立未来任务流后，再研究 Proposer/Reflector 的训练、选择器及连续更新反馈。正式“协同进化”结论需要跨周期、独立来源与可比较资源；单次赛题得分或有限周期调度不够。

这些阶段表示研究依赖，不是阻止正常探索的审批关卡。Q1 和 Q2 可以在数据允许时并行，负结果可以终止无效机制。**先寻找决定性证据，再引入新的学习机制。**

## Harness—权重协同：Evo² 的可检验启发

[Evo²: Evolving the Evolver through Weight-Harness Co-Evolution（arXiv:2610.13025v1）](https://arxiv.org/html/2610.13025v1)提出单个共享策略扮演 Proposer/Reflector：Proposer 自主编辑或按反思建议编辑 Harness，Reflector 依据真实执行反馈决定修订、合并策略或保留；被测试的编辑/结果可通过编辑提取、前缀续接构成训练轨迹，再以 SFT 和交错 GRPO 改进提出与反思行为（EvoTIDE）。**论文的进化器不是必然等于任务执行模型**：比较 Harness 改变时需固定任务执行器和权重，比较进化策略训练时需固定搜索条件及评价来源。

要区别论文中的两组主要结果：表 1 报告 Harness 搜索对 Polyglot 82.1%、SWE-bench Verified 48.3%（对应比较方法最高 62.6%、41.0%）；**不是训练任务执行模型权重后的增益**。表 5 的 EvoTIDE 进化器训练消融为 Polyglot 61.8→78.0、SWE-bench Verified 46.0→51.0，其中后者标注 p=0.086，不能据此断言在常用阈值下有显著收益。表 3 固定商业模型权重、使用 SWE-bench Verified 60 题子集，GPT-5-mini 的 24.4→48.3 是对照方法与 Harness 搜索方法之差，不是该模型的权重微调收益。论文报告跨编程基准及记忆基准迁移，但不等同于 CoEvo 的长期个人科研泛化。上述表格数值按论文公开检索表格及摘要核对，暂未完成原版 HTML 全文逐段验证；正式复现须以该版本原文为准。

CoEvo 的新假设是：**即使 W0 固定，能使 Agent 在错误后重新选择方法、保存执行工件、避免重复调用的通用 Harness 也可能改善未来工作；若持续积累“修改提议—修改前后执行—真实得失”，更好的进化策略可能从中学习。** 反例是：thinking 配置正确后已能独立恢复，Harness 修改没有增量；或改进只对 MCM 数据格式有效、对另一任务退化。

近期不复制 Evo² 的开放 Harness 树搜索、跨分支 crossover 或双角色 GRPO，而是在现有 Pi 中考察**有限、可复核且可撤销的 Harness 变更**：例如面对相同状态的重复工具失败，暴露真实错误摘要并要求更换诊断办法；或在保留原始证据的同时以状态保真续接避免上下文耗尽。具体错误答案、数据清洗代码、评估器和权限策略不属于可演化 Harness。拒绝“为提高得分修改检查器、读取隐藏真值或加宽权限”。

先完成 thinking-on 的正确接入与工作任务实测，再在固定 W0、相同 checkpoint/反馈与可比资源下比较原始 Harness 和候选 Harness；独立测试程序结构之外的迁移。只有存在可复用的 Harness 改进记录、可靠任务级反馈和多个独立来源时，才研究训练共享的 Proposer/Reflector；不先假定 GRPO 优于基于轨迹的 SFT 或固定反思规则。Q1 的经验、Q2 的任务模型训练与这条 Harness 路线可并行，关键是收益归因清晰。

## 技术取舍与现实边界

保留现有 Pi/momo-code、vLLM、Transformers/PEFT 和 RTX 5090 D 32GiB（主机约 96GB）研究环境；32GB 无独显笔记本尚未通过实际部署验收。Qwen 131072 输入 token 曾有资格成功，但这不是长期正确性的保证。

[Spark-X2.5-4B](https://huggingface.co/XHToken/Spark-X2.5-4B) 在官方报告中具有较强编程与 Agent 表现，且采用不同工具/训练模板；官方跨模型跑分不是 CoEvo 的公平实测。其原生长上下文声明不代表单卡可经济运行 1M tokens。引入新底座必须保证模型条件、训练载入、工具解析和推理成本可比；不为其新增一套长期并行运行架构。

[QwenGyre](https://arxiv.org/abs/2609.33848) 提供的启发是长期分叉轨迹、共享前缀去重和超时部分成果评分。当前采用现有原生 Pi 会话与完整轨迹记录；仅当实际复杂任务显现分支冗余/训练成本时，才实现轨迹树或 trajectory-level RL。单卡不复制其多 GPU Elastic Scheduler。

## 已有结果及结论边界

已实测 Pi 工具执行、原生续接、纠错讨论、候选选择、BF16 LoRA 更新及磁盘回载。开发面板 W0 6/16、部分候选 8/16，改善集中在 hash 族；同池三选择策略均 8/16。一次外部经历对照中，原生/完整历史为 11/12、自由笔记为 7/12；一轮笔记修订中仅自审 11/12、反馈修订 7/12。它们是小规模、单种子、共享程序族的 D/G 证据，**没有**正式 H、可归因的长期 R×W、跨结构参数迁移或多流持续收益。MCM 完整首次 W0 执行约 12.8 分钟、71 次工具调用，相同失败命令重复 62 次，无成果；反馈后的两段原生续接累计约 27.4 分钟、14 次实际工具调用，16K 输出限制生效但在 `1906*` 转换错误处重复四次并触发资源停止，仍无持久化建模成果。原 BOM/Year 问题未证实修复。两者均为 D，反馈与调整预算的作用不可独立归因。旧数值以[历史实验报告](../experiments/real-work-foundation/stage-update-2026-10-14.md)为准，新结果以[纠错续接记录](../experiments/mcm-2025-c/feedback-recovery-results.json)为准；不将新范式纳入文档视为机制已实现。
