# AGENT-MODEL-RSI：日常工作中的 Agent—模型持续学习

**状态：研究设计，尚无正式长期 RSI 结果。** 历史方案与试跑证据通过文档导航查阅。

## 问题与研究价值

普通人长期重复的文件、文档、表格、信息整理和个人事务，具有可迁移的操作规律，也持续出现指令变更、用户纠错、工具失效和过时习惯。以这些真实工作研究 Agent 的长期自适应具有明确的应用价值。**尚待检验的是**：外部经验和模型参数能否在相近资源预算下产生独立、可迁移且可持续的净收益。

底座为 **Qwen/Qwen3.5-4B**。模型应可靠遵循当前有效指令，完成能力及工具范围内的日常工作；缺关键信息时询问，缺权限时停止，工具失败时合理恢复，确实做不到时如实说明，并准确报告操作结果。

## Q1–Q3

**Q1 经验应该存放在哪里？** 对一次交互，系统能否判断不学习、保存实例、形成带适用条件的 Skill、提出参数学习候选，或撤回无效经验？相比无条件保存、普通历史检索，是否减少错误沿用并提高未来类似工作的完成率？

**Q2 参数学习是否有独立价值？** 在来源、工具和训练预算可比时，LoRA 能否使未见日常任务的正确执行、指令遵循和能力边界判断有所改善？旧技能、撤回指令、过度拒绝和无依据完成宣称是否恶化？

**Q3 是否存在真实的双向反馈？** 经参数更新的 Wt 是否能比冻结的 W0 更好地提炼经验、筛选新训练候选，并在下一次从相同 checkpoint 出发的更新中产生更高的独立任务收益？多周期效果能否超出更多历史信息、更多计算与测试反馈所解释的改善？

`K` 为指令来源、作用域和生命周期；`R` 为外部经验的提炼、适用条件及检索；`W` 为模型/Adapter 权重；`S` 为训练候选选择。四者用于实验归因。一次交互可以只用于当前任务，也可以在授权和证据充分时进入外部经验或参数学习候选。

## 任务和数据

学习以真实交互过程、实际工具调用与返回、可见的计划和纠错依据为核心。任务可以来自实际工作、受控重建或合成场景；可按工具契约、局部行为与整任务结果分层核验，不要求所有片段先完成历史任务复位。主要应用任务来自 CoEvo 研究仓库之外的日常工作：文件整理、批量命名、按用户约定编辑文档、表格规范化/核对、根据指定材料提取信息、维护本地清单及有界工具操作。简单 JSON 排序、求和、去重用于接口诊断。正式工作流需可重置、可检查结果、能记录真实用户纠错，并使用已接入且获授权的工具。

每个任务程序族设置 `transferable`（已有经验适用）、`unrelated`（无必要迁移）、`reversal`（旧条件失效），还需有可执行、缺信息、缺权限、工具故障、确实超出能力的对应任务。应执行任务上的无故拒答与无法完成时的虚假完成宣称，分别计为行为错误。

来源、意图反馈、客观结果、工具版本、当前有效指令、持久化许可、训练许可及失效状态分别记录。私人交互默认只有本次任务使用权，不能自动成为长期记忆或微调数据。模型自评用于候选提议和诊断；工具结果与独立检查器用于确认完成。任何外部示范均应标明来源，并与模型独立执行记录区分。

采用 `L` 学习流、`D` 开发、`V` 选择、`G` 版本回归、`H` 封存确认。原任务、派生摘要、技能和纠错保留共同 `source_cluster_id`；结构泛化还需按 `program_family` 留出。H 的内容和结果不得用于训练、检索、选样、调参或版本晋升。

## Q1：外部经验与指令

在 W0 冻结时比较：`K0` 强简单来源及撤回规则、`K1` 带条件替代和生命周期管理；关注失效指令沿用 FAR、有效要求遗漏 FDeR 及完成率 ETS。选定固定 `K*` 后，比较 `M0` 无历史、`M1` 普通记录/摘要检索、`M2` 条件化程序性 Skill、`M3` 增加失效管理。共享合法证据和检索预算，另计经验构造、核验、人工费用。策略性固化还应对照固定规则或同池随机选择，候选选择的价值由未见任务中的收益与成本衡量。

## Q2：模型权重、抗遗忘与归因

核心 `2×2` 为 `A=R0W0`、`B=R1W0`、`C=R0W1`、`D=R1W1`。在同一独立任务面板测量 `ΔW=C−A`、`ΔR=B−A`、`ΔW|R=D−B` 以及交互 `I_RW=D−C−B+A`。同一合法来源池构造可训练候选与外部经验；不能让任何组额外获得 H 信息。

已有训练仅 6 条合成任务、327 监督 token、6 步 BF16 LoRA，更新后旧任务 3/3→0/3。首先核对 chat template、工具 schema、训练监督 mask、学习率和 Adapter 加载，并由只监督 write 改为对**经核验的完整 Assistant 行为**监督：读、工具选择和参数、观察结果、纠错、合理询问与停止。退化的具体原因仍需诊断。

优先借鉴 OpenBMB 的 [Self-Replay Fine-Tuning](https://openbmb.cn/en/blog/self-replay-fine-tuning)：用更新前冻结 checkpoint 在独立通用任务上自生成行为，经过筛选后与合法的新任务轨迹混合 SFT。公开 Counting 实验的 Task:Replay **4:1 是样本数比例**，是原实验配比；约 80%–99% 的一般能力下降缓解是作者技术报告在特定模型和任务上的报告结果。区分等监督 token 的普通 SFT 对照与额外 replay 的实用成本，记录回放来源、训练 token、旧能力和新任务结果。保留 W0 作为原始能力锚点，并观察 Wt 自生成 replay 在跨周期更新中的错误累积。

参数学习与外部经验并行研究，选择后续算法时以实际训练结果为依据。

## Q3：机制与真实长期运行

**同池实验**：`SF` 由 W0 选样、`SU` 由本组已接受的 Wt 选样、`SR` 分层随机选样。面对同一合法候选池和预算，从**相同前周期 checkpoint** 训练，利用独立未来任务识别选择机制收益。

**真实闭环**：不同策略在同分布任务流、相近反馈机会和累计预算下分别执行、积累经验、选择更新并接受或拒绝模型版本。保留“权重冻结、经验可更新”对照。策略分支隔离状态、检索索引、模型与可写工作区。该实验估计完整政策收益，并与同池实验测得的选择机制收益区分。

至少记录下一周期首次执行结果、旧任务保持、经验错误复用、虚假完成、错误拒绝、用户纠错负担及全部资源。三周期只能证明工作链基本连贯；正式长期结论需要多个独立任务流、任务来源和训练种子。

## 实施边界与证据

先打通真正可执行且可检查的日常任务、正确询问/停止和合法交互记录，再建立完整行为 SFT + SRFT 和版本回归；Q1 与 Q2 的有效基线可并行发展，之后实施 Q3。工作站 RTX 5090 D 承担训练/集中评价，32GB 无独显笔记本随后验收。现有 131072 输入 token 的资格成功只证明特定长文本定位及工具续接可行，全面长上下文能力及训练序列长度分别根据实际任务测量和设置。

允许只观察到外部经验有效、参数更新无净收益、正收益伴随错误习惯残留，或多轮运行稳定但缺乏真实 RSI 效果。**日常工作的研究意义已明确，具体机制收益必须由独立证据判定。**

相关研究：[SkillRL](https://arxiv.org/abs/2602.08234)、[SkillLearnBench](https://arxiv.org/abs/2604.20087)、[WikiSkill](https://arxiv.org/abs/2608.27454)、[MSCE](https://arxiv.org/abs/2607.16621)、[SEAL](https://arxiv.org/abs/2506.10943)、[SRFT](https://openbmb.cn/en/blog/self-replay-fine-tuning)。

2026-10-14 范围澄清：日常工作按用户实际重复活动界定，包括软件开发和科研分析，不以文件/表格类型限制可探索的学习来源。用户授权的多工作区 Codex 可见轨迹作为教师来源，保留来源、工具反馈和评价曝光；任务复杂度与 4B 可学习性由分层实测确定。表格资格更新和教师导出的实际状态分别见[表格记录](../experiments/everyday-tables/progress.md)、[教师轨迹记录](../experiments/codex-teacher/progress.md)，不替代 Q1–Q3 正式归因。

## 交互驱动 Agent 学习的实施补充（2026-10-14）

用户进一步明确初始设想：交互首先促进 Agent 工作方式的适应，Agent 再提炼信息推动模型学习，更新模型进一步改善执行与提炼。外部经验和参数学习继续并行，但不能以研究助手维护代码或手工编写 Skill 作为被研究 Agent 的自主学习证据。

被研究 Agent 应实际依据请求、工具观察和纠错，提出保存实例、形成带条件 Skill、暂不学习及训练候选选择；固定外部控制器核验来源与合法目标，记录拒绝和版本。提议内容在受控任务中作为有来源的经验数据试用，不自动提升为指令、权限或已验证知识。评价包括提议质量、后续首次执行、错误复用和实际成本；参数更新是否改善提炼/选样必须另有同池预算和未来任务对照。

当前接入开发试点：同一合法 L 池由 W0 与未晋升训练候选分别提议；未来任务统一 W0 执行，比较无记忆、固定规则和模型提议经验，隔离提议权重与执行权重。该候选已接触这批学习来源，仅能检查机制与开发行为，不能作为正式 Q3 泛化结论。模型提议训练目标仍需既有目标证书；未核验的 Skill 文本不直接进入 SFT。正式同池交叉重训与独立任务流保持后续职责。

### 当前实施优先级：原生上下文与开放学习表达

用户进一步要求活的 RSI，并指出当前模型可以保持原生上下文。学习过程优先沿原任务会话连续开展：完成工作、接收反馈、复盘、选择下一项尝试、再次执行，再决定哪些真实片段用于参数学习。不强制经验提议采用预设 JSON 或条件白名单；结构化表示只在具体检索、执行或训练接口需要时转换。来源由控制器绑定，执行许可、资源预算和实际结果核验仍按任务记录。既有严格提议 schema 试点保留为历史比较，不再是当前学习表达的统一前置门槛。

已接入原始 Pi 会话续接，不压缩或重建模型的已有消息。自由讨论只是可见学习提议，不因表达完整就成为正确监督；其提出的下一项工作由独立任务环境提供输入和结果检查，并记录环境构造者。原生上下文适应、外部持久经验和参数更新分别评价，不能混作同一收益。
