# CoEvo 研究方案：真实工作驱动的 Agent 递归自我改进

**研究定位（2026-10-15）**：面向个人日常生活与科研工作的智能助手，在长期真实交互中能否通过经验复用、指令生命周期、Harness 改进、模型参数学习，获得真实、可迁移的任务能力净收益，并逐渐**学会更有效地改进自己**？这才是 CoEvo 的递归自我改进（RSI）核心；文档处理、工具调用、资料整理和持续协作是主要真实工作环境。编程是一种有用的工具能力，不是默认核心任务或科研成效替代指标。

**独立路线决定**：CoEvo 保持独立的、可以因研究证据而持续改变的 Agent—模型 RSI 系统。系统性拆解 [PilotDeck](https://github.com/OpenBMB/PilotDeck) 和 [Pi](https://github.com/earendil-works/pi) 的优秀实现与设计，根据本项目真实需要选择性吸收 Office Skills、文件保真、上下文/恢复、记忆和工具机制；不整体迁入 PilotDeck 的 Gateway、UI 或 Agent Loop，也不视 Pi 为不可替换的长期框架。PilotDeck 原生 CLI 技术验证与 Transcript 提取已在 [独立参考入口](../experiments/pilotdeck/README.md)实现，不能理解为 CoEvo 主架构迁移或 RSI 取得进展。接受模型仍为 Qwen3.5-4B W0，Spark-X2.5-4B 尚待实测，无已晋升 W1。

## 科学问题

主要研究对象是完整工作流及其跨时间变化：用户的目标和当时有效约束、原始文档与数据、工具调用及结果、Agent 产生的部分/最终成果、外部反馈、失败修订、计算资源和未来应用。以 K 表示指令范围、时效和撤回；R 表示外部经历与可复用经验；𝓗 表示执行 Harness；W_task 表示任务模型参数；W_evolver 表示提出/反思改进的策略参数；S 表示训练或修改候选的选择策略。这些是因果解释维度，不要求分别部署独立服务。H 表示未曝光评价来源，不与 𝓗 混用。

**Q1——经历何时产生未来收益？** 对比无历史、原始经历、PilotDeck 自带记忆、条件化经验/Skills 的实际帮助；检验用户一次性要求被错误长期化、旧结论被撤回后误用、跨项目污染和经验失效。完整经历可能优于摘要，关闭记忆也可能更好。

**Q2——哪些经历适合写入权重？** 从合法且可核实的成功行为、有效部分工作、反馈后正确修订中提取学习目标，判断 W0→W1 在新会话、不同任务中是否改善交付，是否遗忘旧能力。训练无需等整个复杂任务完美完成，但错误结果、标签泄漏、外部教师代劳不能冒充模型自主正确示范；辅助来源可以用于学习但应明确标记。

**Q3——系统是否学习了改进自身的方法？** 严格区分研究者修复、Agent 自主提出并实施有效修改，以及系统利用过去的改进经历，在**后续不同任务中更善于提出、筛选、执行和保留新的有效修改**。前两者不等于第三者。可进化对象包括经验选择、Skills、通用工作方法、Harness 以及在条件允许时的参数和改进策略。RSI 结论应来自多轮未来任务的有效变化，而不是学习脚本运行或模型自我描述。

**自然循环**：真实工作及反馈 → Agent 识别可改进问题 → 提出并实施有依据的经验/Harness/权重等修改 → 后续工作检验净效果 → 从修改得失中更新下一轮改进策略。没有必要要求每轮同时使用所有机制、每个失败都产生新模块或每条工具动作都单独核验。允许外部参考帮助，但必须区分谁完成了什么。

## 当前证据与路线调整依据

[早期同程序族实验](../experiments/real-work-foundation/stage-update-2026-10-14.md)已验证 Pi 原生工具会话、BF16 LoRA 训练/加载；某些候选由 W0 6/16 改善为 8/16，集中在哈希任务，Replay 或选样并无稳定附加收益。一组经历对照无历史 7/12、原生/完整历史 11/12、自由笔记 7/12：表明表达形式有影响，但仍非独立跨来源学习确认。[MCM C](../experiments/mcm-2025-c/README.md) 的 thinking 续接保存源码却未交付有效预测，且存在统计问题。

最新[两项完整真实工作](../experiments/complete-work/README.md)属于开发 D：软件维护历时 27.3 分钟耗尽工具额度，原有 56 项测试通过但核心冲突未修复、新增测试无法收集；Palmer Penguins 科研分析历时 25.1 分钟，源码/图表/报告独立复跑一致，描述统计和部分回归系数可复核，但“置信区间”、调整均值、缺失并集和重复个体解释仍错误。这比大量微型动作更能揭示可靠任务理解、真正完成与自我修订的缺口。后续[科研原生反馈续接](../experiments/complete-work/science-feedback-results.json)历时 13.3 分钟，修正均值区间并加入可重算的回归，但调整均值、个体身份、缺失与图文一致性仍有关键错误；这提供有辅助标记的有效部分，尚未形成完整科学交付。

这些结果均**没有**证明正式的长期 RSI 或跨领域参数收益。[PilotDeck 参考试跑](../experiments/pilotdeck/reference-results.json)未取得完整任务成功；独立 [Pi Office 任务](../experiments/pi-office/README.md)已取得反馈辅助下的正确工件，但首轮失败、模型总结含错误。旧任务与历史模型版本应完整保留，但不继续围绕相同程序族堆积测试或重建另一套通用 Agent 框架。

## 研究任务生态与底座决策

优先使用有真实工作价值的完整任务：修改既有 Word、Excel、PPT 文件并保留未授权内容；整理和更新科研文献/研究材料；处理真实表格、科学数据及论证；跨会话持续推进同一个项目，正确响应新的条件、撤回和反馈。完成标准是实际可用交付及必要的事实/科学证据，不是文件可打开、渲染漂亮或代码退出 0。真实工作可以长短不同，不要为追求样本数把它们拆成机械的微型核验。软件开发和 MCM 保留为能力范围内的任务，不继续垄断研究主线。

默认研究环境继续采用 CoEvo 可控的 Pi SDK 任务执行入口，并按需吸收可独立复用的上游实现；PilotDeck 原生 CLI 是参考与比较条件，不是必须依赖的主环境。必要时允许强参考 Agent 提供合法指导。日常最佳产品可以使用多模型路由，科研研究需记录路由/云端介入，避免将更换大模型或更换 Harness 的收益归于 RSI。底座 Qwen W0 与 Spark 候选的选择应优先由实际办公/科研交付、推理成本、单卡训练适配决定，而非代码排行榜；PilotDeck 采用哪种模型模板/工具解析必须真实运行后才确定。

优先选择适于原始文档定向修改、格式及公式保留的上游 Skills 和实质工具代码；可独立使用的机制直接复用，高耦合设计仅提炼对 CoEvo 有价值的部分。Pi 1.2.0 原生 Skill 加载与明确的结束语义可用于改善当前适配器，其他上游变化按实际任务需要选择；不为追赶版本全量搬运，也不因 Pi 或 PilotDeck 存在而限制未来自主演化。

## 决定性证据与研究参照

近期应通过 CoEvo 原生任务和精选成熟 Office 技能积累真实工作与反馈改进的有效经历，再把实际经历用于 Q1/Q2 和自主改进 Q3；不将步骤设计成一连串形式化 Gate。评估持续工作和未来新来源中是否提高用户成果质量、减少重复指导、降低错误和返工，及 Agent 是否逐渐更会改进自己的工作方式。允许负结果促使缩减、替换或放弃机制。

- [PilotDeck](https://github.com/OpenBMB/PilotDeck)（本次审阅固定 main@783499ffdb2d501bf590b2e035acd027a882df10）已有通用执行、Skills、插件/Hooks、Transcript、记忆、检查点等代码。宣传中的 WorkBuddy Bench 79.1 和 2000 条消息压力测试，本轮未找到可独立核对的完整评测/恢复记录，不作为选型定量证据。
- [Harness²（arXiv:2610.14224）](https://arxiv.org/abs/2610.14224)区分当前任务 Harness 修改与从修改过程学习跨任务改进策略，接近 Q3 核心；其较强模型/基准结果不能直接推广到本地 4B。
- [OfficeEditBench（arXiv:2609.34469）](https://arxiv.org/abs/2609.34469)证明办公室文件可打开与目标改动完整、原内容保真是不同要求。[LongMemEval-V2（arXiv:2605.12493）](https://arxiv.org/abs/2605.12493)关注从长期 Agent 轨迹学习工作流、状态变化、失败条件；[LongMemEval（ICLR 2025）](https://arxiv.org/abs/2410.10813)关注长期对话的知识更新、时间推理与弃答。这些是机制线索，并不代替实际任务评价。
- [RSIGym（arXiv:2610.10310）](https://arxiv.org/abs/2610.10310)、[Evo²（arXiv:2610.13025）](https://arxiv.org/abs/2610.13025)支持训练/Harness/改进策略的分离研究，也提示局部训练成绩并不保证总体能力净增益；单 RTX 5090 D 32GiB、约 96GB RAM 无需复制多 GPU 服务或复杂搜索体系。

科学结论怎样成立见[评价与统计](评估与统计.md)，已确认集成接口与实施边界见[实施与复现](实施与复现.md)。Pi 1.2.0 的任务执行和反馈恢复已有实测；后续重点是经验能否经真实检验改善未来工作。当前单次修复不足以识别跨任务迁移或递归改进。
