# AGENT-MODEL-RSI：日常工作中的 Agent—模型持续学习

**状态：研究设计，尚无正式长期 RSI 结果。** 本文吸收用户提供的研究方案 v0.5、三份调研及后续讨论，不擅自引入新版本号。历史 v0.4 方案和试跑记录保留，既往结果不按新门槛追溯重判。

## 问题与研究价值

普通人长期重复的文件、文档、表格、信息整理和个人事务，具有可迁移的操作规律，也持续出现指令变更、用户纠错、工具失效和过时习惯。以这些真实工作研究 Agent 的长期自适应具有明确的应用价值。**尚待检验的是**：外部经验和模型参数能否在相近资源预算下产生独立、可迁移且可持续的净收益。

唯一底座为 **Qwen/Qwen3.5-4B**。不再进行底座竞争，不引入内置高级 Agent 或多 Agent 团队。模型需要可靠遵循当前有效指令，完成能力及工具范围内的日常工作；缺关键信息时询问，缺权限时停止，工具失败时合理恢复，确实做不到时如实说明，不虚构完成。复杂科研或大型软件工程由用户在其他平台处理，不属于本系统的必备能力。

## Q1–Q3

**Q1 经验应该存放在哪里？** 对一次交互，系统能否判断不学习、保存实例、形成带适用条件的 Skill、提出参数学习候选，或撤回无效经验？相比无条件保存、普通历史检索，是否减少错误沿用并提高未来类似工作的完成率？

**Q2 参数学习是否有独立价值？** 在来源、工具和训练预算可比时，LoRA 能否使未见日常任务的正确执行、指令遵循和能力边界判断有所改善？旧技能、撤回指令、过度拒绝和无依据完成宣称是否恶化？

**Q3 是否存在真实的双向反馈？** 经参数更新的 Wt 是否能比冻结的 W0 更好地提炼经验、筛选新训练候选，并在下一次从相同 checkpoint 出发的更新中产生更高的独立任务收益？多周期效果能否超出更多历史信息、更多计算与测试反馈所解释的改善？

`K` 为指令来源、作用域和生命周期；`R` 为外部经验的提炼、适用条件及检索；`W` 为模型/Adapter 权重；`S` 为训练候选选择。它们是研究因素，不是软件必须划分的四项服务。某条交互可被拒绝长期保存，也可合法地分别用于运行时经验或参数候选，没有必须先进入 Skill 才能训练的升级阶梯。

## 任务和数据

主要任务来自 CoEvo 研究仓库之外的日常真实工作：文件整理、批量命名、按用户约定编辑文档、表格规范化/核对、根据指定材料提取信息、维护本地清单及有界工具操作。简单 JSON 排序、求和、去重仅保留作工程试跑。正式工作流需可重置、可用工具结果检查、能保留真实用户纠错；尚未连接的邮箱、日历或浏览器账户不宣称可操作。

每个任务程序族设置 `transferable`（已有经验适用）、`unrelated`（无必要迁移）、`reversal`（旧条件失效），还需有可执行、缺信息、缺权限、工具故障、确实超出能力的对应任务。**正确不行动不等于全面拒绝**：应执行任务上的拒答是损失；确实无法做时冒称完成也是损失。

来源、意图反馈、客观结果、工具版本、当前有效指令、持久化许可、训练许可及失效状态分别记录。私人交互默认只有本次任务使用权，不能自动成为长期记忆或微调数据。模型的自评是候选或诊断，不是结果真值。外部平台偶然提供的修复或示范应标明来源；项目不建设内部强教师服务，也不能把外部示范算作 4B 自主取得的能力。

采用 `L` 学习流、`D` 开发、`V` 选择、`G` 版本回归、`H` 封存确认。原任务、派生摘要、技能和纠错保留共同 `source_cluster_id`；结构泛化还需按 `program_family` 留出。H 的内容和结果不得用于训练、检索、选样、调参或版本晋升。

## Q1：外部经验与指令

在 W0 冻结时比较：`K0` 强简单来源及撤回规则、`K1` 带条件替代和生命周期管理；关注失效指令沿用 FAR、有效要求遗漏 FDeR 及完成率 ETS。选定固定 `K*` 后，比较 `M0` 无历史、`M1` 普通记录/摘要检索、`M2` 条件化程序性 Skill、`M3` 增加失效管理。共享合法证据和检索预算，另计经验构造、核验、人工费用。策略性固化还应对照固定规则或同池随机选择，不能把候选数量当成学习收益。

## Q2：模型权重、抗遗忘与归因

核心 `2×2` 为 `A=R0W0`、`B=R1W0`、`C=R0W1`、`D=R1W1`。在同一独立任务面板测量 `ΔW=C−A`、`ΔR=B−A`、`ΔW|R=D−B` 以及交互 `I_RW=D−C−B+A`。同一合法来源池构造可训练候选与外部经验；不能让任何组额外获得 H 信息。

已有训练仅 6 条合成任务、327 监督 token、6 步 BF16 LoRA，更新后旧任务 3/3→0/3。首先核对 chat template、工具 schema、训练监督 mask、学习率和 Adapter 加载，并由只监督 write 改为对**经核验的完整 Assistant 行为**监督：读、工具选择和参数、观察结果、纠错、合理询问与停止。旧结果不能证明 LoRA 必然无效或遗忘原因已经确定。

优先借鉴 OpenBMB 的 [Self-Replay Fine-Tuning](https://openbmb.cn/en/blog/self-replay-fine-tuning)：用更新前冻结 checkpoint 在独立通用任务上自生成行为，经过筛选后与合法的新任务轨迹混合 SFT。公开 Counting 实验的 Task:Replay **4:1 是样本数比例**，并非本卡最优比例；报告的 80%–99% 一般能力下降缓解仅在原实验设定下成立。区分等监督 token 的普通 SFT 对照与额外 replay 的实用成本，记录回放来源、训练 token、旧能力和新任务结果。保留 W0 作为原始能力锚点，不预设 Wt 自生成 replay 跨周期无风险。

FINCH、SLoRA、RL、额外 Adapter、改变模型架构都不是当前必选开发项。参数学习与外部经验可以并行研究，不需要等待经验库先“饱和”。

## Q3：机制与真实长期运行

**同池实验**：`SF` 由 W0 选样、`SU` 由本组已接受的 Wt 选样、`SR` 分层随机选样。面对同一合法候选池和预算，从**相同前周期 checkpoint** 训练，利用独立未来任务识别选择机制收益。

**真实闭环**：不同策略在同分布任务流、相近反馈机会和累计预算下分别执行、积累经验、选择更新并接受或拒绝模型版本。保留“权重冻结、经验可更新”对照。策略分支隔离状态、检索索引、模型与可写工作区。该实验估计完整政策收益，不把总收益全部归给数据选择器。

至少记录下一周期首次执行结果、旧任务保持、经验错误复用、虚假完成、错误拒绝、用户纠错负担及全部资源。三周期只能证明工作链基本连贯；正式长期结论需要多个独立任务流、任务来源和训练种子。

## 实施边界与证据

先打通真正可执行且可检查的日常任务、正确询问/停止和合法交互记录，再建立完整行为 SFT + SRFT 和版本回归；Q1 与 Q2 的有效基线可并行发展，之后实施 Q3。工作站 RTX 5090 D 承担训练/集中评价，32GB 无独显笔记本随后验收。现有 131072 输入 token 的资格成功只证明特定长文本定位及工具续接可行，不等同于全面长上下文能力，也不要求训练达到此序列长度。

允许只观察到外部经验有效、参数更新无净收益、正收益伴随错误习惯残留，或多轮运行稳定但缺乏真实 RSI 效果。**日常工作的研究意义已明确，具体机制收益必须由独立证据判定。**

相关研究：[SkillRL](https://arxiv.org/abs/2602.08234)、[SkillLearnBench](https://arxiv.org/abs/2604.20087)、[WikiSkill](https://arxiv.org/abs/2608.27454)、[MSCE](https://arxiv.org/abs/2607.16621)、[SEAL](https://arxiv.org/abs/2506.10943)、[SRFT](https://openbmb.cn/en/blog/self-replay-fine-tuning)。经验→Skill、外部验证、回放和模型自适应已见先例，本研究不把这些机制名称当作原创证据。
