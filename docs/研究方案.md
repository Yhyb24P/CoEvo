# CoEvo 研究方案：长期交互中的经验与参数学习

**研究状态：2026-10-14 阶段性暂停；目前没有正式 H 或多流持续收益结论。** 唯一底座为 Qwen3.5-4B，原始权重 W0 仍是已接受版本。本文是当前研究方向，不覆盖历史实验当时冻结的条件；已有实验的事实见 [阶段总结](../experiments/real-work-foundation/stage-update-2026-10-14.md)。

## 科学问题

研究长期执行真实工作的小模型 Agent：接触任务、观察工具结果、犯错、获取人类反馈、修正并再次尝试后，**哪些行为能力能够迁移到新任务**？经历应留在当前会话、长期外部经验，还是经训练成为参数能力？在有效经验变得不适用或被撤回时，系统能否停止错误沿用？

区分四个实验因素：`K` 为有效指令的来源、作用域和生命周期；`R` 为外部经历/Skill 的保存、抽象与检索；`W` 为模型或 Adapter；`S` 为训练候选选择。它们是归因维度，不要求建设四套服务。授权与客观任务结果由外部环境决定，模型可以建议学习但不能自行确立证据真实性、权限或模型发布。

三项相互关联但不相互代替的问题：

1. **Q1：经历如何保留和适用？** 在 W0 不变时比较原生上下文、完整外部记录、普通记忆及带作用条件的技能；检验可复用、无关、条件反转和撤回的未来任务。复杂表示必须优于强简单历史基线，不能只以笔记完整或自评可信作结论。
2. **Q2：参数更新何时值得？** 从同一合法来源学习，在 R 关闭和开启时比较 W0/W1，测独立未来任务、旧能力、错误宣称及代价。训练变化、loss 下降、旧任务小面板保持都不足以证明净收益。完整正确 Assistant 行为、纠错续接和 replay 是候选方法，不是预设必胜机制。
3. **Q3：双向反馈是否带来增量？** 检验更新后的模型能否更好地提炼/选择新经历，进而改善后续训练。先在相同候选池和 checkpoint 下与冻结选择器及简单随机策略比较，再在彼此隔离的真实任务流中测整套政策效果；二者的归因不同。

## 研究对象与学习路线

基本对象是**完整工作经历**：原始需求、当时有效要求、可见上下文、Agent 行动、工具结果、分支/重试/压缩、用户纠错、产生的工件及后续验证。经历不必全部成功才有研究价值。局部成功步骤可以作为独立核验目标；失败、未完成和超时工件对问题诊断及任务级奖励仍有价值，但不能自动变成正确动作的 SFT 标签。

模型可以在原生会话中自由复盘、修改笔记、提出下一步行动或训练候选；仅在实际执行/检索/训练接口需要时转换成结构化对象。学习动作可是不长期保留、保存可追溯实例、构造带适用条件的经验、提交训练候选、失效/回滚，并不构成强制的逐级升级链。

首要任务是用户真实重复工作，包括软件开发、科研分析、资料与表格处理；受控可复位任务用于可比较的反事实和故障归因，简单 JSON/排序类任务只做接口资格。重要分层为同结构新实例、未见程序结构、未来到达的新任务，以及改变条件、撤回和失败恢复。任务复杂度按 W0 可完成性、改进空间与结果可核验性选择，不按领域名称堆砌任务数量。

## QwenGyre 的取舍

[QwenGyre（arXiv:2609.33848）](https://arxiv.org/abs/2609.33848) 研究极长 Agent rollout 的调度和训练。对本项目最有价值的是保存模型边界处真实轨迹、重建共享前缀与分支、避免同一历史重复计入训练，以及对超时后真实保留的部分工件进行可判定评分。**这些是方法启发，CoEvo 尚未实现其完整轨迹树处理器或 RL。**

多节点 Elastic Scheduler 及论文中大模型、长轨迹的性能数字不应转成单卡 5090 的速度承诺。当前先使用已有 Pi 原生会话和可恢复轨迹，只有当真实分叉产生重复训练成本或需要任务级优化时，才研究树式去重和 RL。避免为“引入新范式”复制一套云端编排。

## 当前证据如何影响研究取舍

本仓库开发实验表明：初次 327 监督 token LoRA 候选旧任务 3/3→0/3；随后相同 W0 起点的多组 SFT 在一个 16 题 D 面板由 6/16 至 8/16，提升集中于 hash 族；同池 SF/SU-proxy/SR 三组均 8/16，未发现选择器差异。经验比较中，原生/完整历史为 11/12，自由笔记 7/12；另一轮修订中仅自审 11/12，反馈修订 7/12。它们都是少来源、单种子、已曝光开发证据，无法形成正式参数泛化、记忆优越或持续进化结论。具体样本与失败结构请读取原始实验摘要，不从这组数字推导机制已成立。

因此研究次序应由失败机制与任务信息价值决定：先解释**哪些经历被成功利用、哪些条件在提炼后丢失，以及完成宣称为什么与实际工件不一致**；在足够多不同结构的新任务上检验效果；若出现确实需要参数固化的重复缺陷，再设计训练或 RL 对照。Q1 和 Q2 可以并行推进；不必等待某条机制取得正结果才研究另一条。Q3 需要前两者真实可用的更新政策和足够独立的未来任务流。

研究允许外部经验有效但参数无收益、权重有效但无交互、闭环运行正常却无长期改善。只有排除额外信息、数据机会和资源差异并有独立纵向证据，才把性能结果称为“协同进化”。
