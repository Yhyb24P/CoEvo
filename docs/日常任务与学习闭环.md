# 日常任务与学习闭环

首批拟研究的日常任务如下；它们不限制用户实际日常工作范围。用户于 2026-10-14 明确将软件开发、科研分析等多工作区工作纳入可探索的学习来源。历史合成 read/write 试点及后续 Marko read/write/bash 开发试跑已经记录；日常真实任务和长期用户纠错流尚未建立，实际边界见[开发试跑记录](../experiments/project-tasks/progress.md)。

| 程序族 | 日常任务 | 应学习的行为 |
|---|---|---|
| 文件 | 查找、归档、重命名、重复文件处理建议 | 规则适用条件、目录许可、用户修改 |
| 文档与笔记 | 局部修改、格式整理、信息摘录 | 临时要求与长期习惯冲突 |
| 表格 | 列名归一、筛选、汇总、模板转换 | 缺字段、歧义、校验结果 |
| 信息和清单 | 指定资料提要、待办维护、更新记录 | 时间有效性、已完成/撤回事项 |
| 开发与科研工作 | 代码维护、分析脚本、实验与技术文档 | 工具判断、结果核验、纠错和可迁移领域能力 |
| 有界本地工具 | 按许可操作、出错后纠错或停止 | 正确工具、授权和执行能力边界 |

在重复但不同来源的任务中观察经验迁移，设置有效、无关及条件反转的任务；成对覆盖可执行、缺信息、缺权限、工具不可用、模型不能完成的情况。产品层关注重复指导与纠错是否减少；Q1–Q3 区分经验、参数与递归反馈的贡献。

交互学习流程：保存**当前授权**的有效指令和任务状态 → Qwen3.5-4B 执行、询问或有据停止 → 工具结果与用户纠错 → 来源/权限/正确性确认 → 不学习、保存实例、形成有条件 Skill、列入参数训练候选或撤回 → 已授权的完整正确行为 SFT 与 SRFT → 旧能力/新任务评价、接受或回滚 → 下一次真实任务。

私人交互的执行许可不代表训练许可；账户权限、用户偏好、文件路径和动态事实必须能够在外部状态撤回。模型可提出技能或选样建议，采纳依据为外部核验与后续任务效果。外部学习和参数学习可以并行推进。

2026-10-14 已建立受控表格程序族与目标级核验并完成一次资格更新，见[实际记录](../experiments/everyday-tables/progress.md)。Codex 历史可见交互按教师来源导出到本地；原始导出与可训练目标分开，保留工作区/会话来源、工具结果、失败和评价曝光标记。研究者或教师完成的任务不能记作 Qwen 自主能力；工具格式适配与独立结果核验后才进入合法学习集合。

执行补充：整任务成功不是每个学习片段的统一准入门槛。保留真实工具参数、返回、可见计划及观察后的后续动作，按实际证据支持的行为粒度形成目标；工具观察保留为上下文。已核验的片段可先训练，任务复位和完整成功检查用于需要它们的目标及独立评价。
