# 日常任务与学习闭环

首批拟研究的日常任务如下。历史合成 read/write 试点及后续 Marko read/write/bash 开发试跑已经记录；日常真实任务和长期用户纠错流尚未建立，实际边界见[开发试跑记录](../experiments/project-tasks/progress.md)。

| 程序族 | 日常任务 | 应学习的行为 |
|---|---|---|
| 文件 | 查找、归档、重命名、重复文件处理建议 | 规则适用条件、目录许可、用户修改 |
| 文档与笔记 | 局部修改、格式整理、信息摘录 | 临时要求与长期习惯冲突 |
| 表格 | 列名归一、筛选、汇总、模板转换 | 缺字段、歧义、校验结果 |
| 信息和清单 | 指定资料提要、待办维护、更新记录 | 时间有效性、已完成/撤回事项 |
| 有界本地工具 | 按许可操作、出错后纠错或停止 | 正确工具、授权和执行能力边界 |

在重复但不同来源的任务中观察经验迁移，设置有效、无关及条件反转的任务；成对覆盖可执行、缺信息、缺权限、工具不可用、模型不能完成的情况。产品层关注重复指导与纠错是否减少；Q1–Q3 区分经验、参数与递归反馈的贡献。

交互学习流程：保存**当前授权**的有效指令和任务状态 → Qwen3.5-4B 执行、询问或有据停止 → 工具结果与用户纠错 → 来源/权限/正确性确认 → 不学习、保存实例、形成有条件 Skill、列入参数训练候选或撤回 → 已授权的完整正确行为 SFT 与 SRFT → 旧能力/新任务评价、接受或回滚 → 下一次真实任务。

私人交互的执行许可不代表训练许可；账户权限、用户偏好、文件路径和动态事实必须能够在外部状态撤回。模型可提出技能或选样建议，采纳依据为外部核验与后续任务效果。外部学习和参数学习可以并行推进。
