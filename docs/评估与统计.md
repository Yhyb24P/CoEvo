# CoEvo 评价与统计：完整成果、学习来源与长期净收益

[研究方案](研究方案.md)规定真实完整工作与 Q1/Q2/Q3；本文只规定**什么证据能改变科学判断**。不为每次 read、write、bash、checkpoint 或错误修补建立单独科学门槛。已有软件测试维持技术正确性；研究评价关注后续工作的实际成果和能力变化。

## 评价单位与信息边界

主要观察单位为一次**完整工作流/episode**：需求、开始时可见材料、有效指令、执行与反馈、文件/模型状态、真实成果、失败和成本。由同一题面、数据、程序族或同一工作流派生的多个续接、回测和扰动共享来源簇；它们可以用于机制分析，不能冒充独立未来任务。一个 episode 内的工具调用、国家数量或分支数量不是独立样本量。

维持 L（合法学习来源）、D（开发探索）、V（机制选择）、G（必要回归）、H（未曝光的科学确认）区分；阶段标签不等于项目进度审批。已看过的公开基准与 MCM 原题不得因为更换随机种子就转为封存 H。来源信息随派生经历、总结、监督目标和 Harness 修改传播；私人经历的任务使用、存储、训练与公开许可分别处理。

完整任务的质量需结合实际要求判断：有效产出、科学或工程正确性、可用性、独立复现、是否真实解决目标、人工介入程度，以及合理资源消耗。可以报告有用的部分成果和失败，而不是只算单一完成率。对于没有客观即时真值的预测，应评价当时可检验的方法合理性及历史滚动表现，不能捏造未来真实误差。代码存在、模型宣称成功、进程退出码 0、报错减少与检查器阻止危险操作均不足以证明能力提升。

**归因标签必须贯穿工作**：无辅助自主完成、用户反馈后继续、研究者/强参考 Agent 提供指导、研究者直接完成、验证器拦截/替修、系统环境失败和资源中止。不因最终工件正确而抹掉过程中的外部贡献；有指导形成的经验仍可作为合法学习候选，但不能记作独立解决能力。

## 科学数据与软件任务的实质评价

对软件工作，首要看真实需求是否得到满足，最终代码和系统能否在约定环境中工作，变更是否引入实质回归。单元测试是证据之一，不代表需求理解、完整交付或跨任务迁移。

对科学分析，既关注实际可执行程序、数据处理与结果交付，也关注**预测时点、特征与目标的因果/时间关系、模型假设、数据泄漏、推断有效性及可重复计算**。科学判断错误不能被格式合规或拟合高分抵消；真实完成中的合理局部限制也不必一律按失败处理。外部复核和模型独立自我纠错必须分别计入。

[2025 MCM C](../experiments/mcm-2025-c/README.md) 的具体成果包括金牌/总奖牌预测及区间、首获奖牌国家、项目结构分析、教练效应的适当证据边界、三国建议和完整报告。历史回测按预测年份严格约束当时可见的奖牌、运动员、主办信息和预处理；官方现代回顾性导出不是可靠的历史版本快照。奖牌表只覆盖获牌队伍，零奖牌代表队与历史 IOC 身份必须纳入定义。金牌数/总奖牌数可用滚动预测误差及简单基线判断；区间同时报告覆盖与宽度，首获牌概率应有正确的风险总体及可解释的校准依据。2028 尚无真值，因此任何 2028 准确率都是无依据的。MCM 全部既有执行均为 D，同赛题产生的更多执行不增加独立 H 来源。

## 识别 Q1、Q2、Q3 的证据

**Q1（经历）**：固定任务模型与任务环境，比较未使用经历、原生可回放历史、外部经验及条件化经验。比较重点是未来完整工作是否更好、是否迁移到新来源、旧结论是否在条件变化后正确退出，同时报告经历获取/读取成本。不同记忆方式可以包含不同信息；相同 token 数不自动等于等信息量。

**Q2（权重）**：在确实存在合法、可验证的训练目标后，从同一 W0 和可比学习来源产生候选，观察未见任务的实际工作质量、旧能力和成本。有数据时使用 R0W0、R1W0、R0W1、R1W1 区分外部经验、参数及其交互；在数据不足时可先形成较窄、明确范围的结论，不为凑齐设计制造大量合成任务。完整正确轨迹与经外部纠正的有效部分轨迹均可成为候选，须保留贡献来源；错误标签、教师代劳、目标泄漏不得自动正向监督。无效训练与遗忘是研究结果，不应反复追加训练轮次掩盖。

**Q3（自主改进）**：分清由研究者提供 Harness 修复、Agent 独立提出/实施的修复、训练 W_evolver 后产生的更有效修复。评估时固定任务执行模型、可演化权限/范围、可见反馈和探索资源，比较选出的 Harness 在**没有参与选优的未来完整任务**上的质量。进化策略学习则需进一步比较未更新与更新的策略在未来提出、诊断、选择并实现有效修改的能力；不能只检查提议格式、改动次数或搜索流程是否完成。W_task 改善任务能力与 W_evolver 更善于改进系统是不同因果效应。

底座选择与学习效果分开报告：Qwen3.5-4B W0 与 Spark-X2.5-4B 候选在相同任务机会、合法资料、工具权限和相称的墙钟/GPU 资源下运行；允许各自使用正确原生推理模板和推荐采样，但须公开对应条件、投入与完成质量。跨模型绝对得分不同并非协同进化。

## 统计、成本与停止无效工作

完整任务可以异质，勿用单一分数掩盖质量差异。先报告每条工作的有效交付及关键失败、与合理基线的比较和实际成本；有足够独立来源时，再按任务来源或连续工作流配对估计效应及不确定性。连续周期不仅考察新任务，还要关注旧能力保持、反馈需求是否减少、条件化经验是否误用，以及未来自主改进的质量。多次随机重复用于判断随机性，不能将同源重复当作泛化样本。

记录真正影响解释的资源：模型与推理配置、时间、GPU/显存、输入输出 token、工具与训练成本、外部指导。不同推理模式同时改变采样、上下文和输出上限时，只报告配置组合差异，不进行 thinking 单因素因果宣称；旧预算超额保持原始事实。重复失败保护和时间限制属于资源控制，不给模型“自我修复”加分。

H 的确认任务必须在用于训练、机制选择和反复查看结果的开发来源之外；正式测试前确定主要研究问题和结果口径，随后允许按新的未曝光任务继续研究。若没有这种条件，诚实报告“同源开发变化”而非“可持续泛化”。

评价投入必须能排除重要竞争解释、改变研究决策或保护必要权限和科学证据。局部程序回归无需升级为科研实验；一旦多个执行暴露相同系统性失败，应重新判断模型、任务选择与学习方法，而不是无期限增加核验密度。
