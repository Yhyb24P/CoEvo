## 2. 五个职责边界

| 职责 | 负责内容 | 边界 |
|---|---|---|
| 研究平台 CoEvo | 实验因素、运行记录、划分、训练决策、版本和评价证据 | 不默认作为被研究 Agent 的任务仓库 |
| 被研究 Agent | 当前 Qwen3.5-4B + Pi SDK 执行实际任务、调用工具、生成轨迹 | 学生能力依据学生实际执行结果 |
| 独立任务环境 | 真实代码、文件、终端任务，可复位并由检查器确认结果 | 检查器及隐藏答案与 Agent 隔离 |
| 学习模块 | 实例与技能管理、候选选择、LoRA 训练和回滚 | 模型提议不改变来源权限或训练准入 |
| 评价模块 | 可验证结果、封存任务、统计归因、风险与成本 | 发布回归 G 与科学确认 H 分开 |

这些是职责边界，无须拆成五套服务。核心逻辑按实际使用放入共享模块，`rsi.py` 负责调度。研究助手、强教师、用户纠错与学生输出分别记录；助手开发 CoEvo 或提供示范不计作学生自主能力。

## 4. 工作批次与依赖

**批次 A（T00–T03）：统一研究基础。** 将 v0.5 纳入仓库，确定真实任务环境，完善执行与交互记录。最小闭环是小模型实际执行、独立检查、反馈与正确续接；用户纠错、外部结果、教师示范和学生输出可区分。

**批次 B（T04–T06）：并行建设。** B1 建设 Q1 的技能提炼、条件化检索、失效与撤回；B2 诊断 LoRA 退化，建设完整轨迹 SFT 与 Replay 基线。两线共享合法学习来源，但分别记录干预及实验版本；不以经验库饱和作为训练前提。

**批次 C（T06–T08）：科学对照与反馈。** 经验和参数机制形成可比较版本后，先做正式 R×W，再做共享候选池机制实验，最后做真实任务流多周期政策研究。长上下文与撤回验证贯穿相应比较；三个周期不是成功标准。

**批次 D（T09）：部署验证。** 工作站研究、回归和版本管理形成可靠结果后，才进入笔记本部署。批次 A–D 是任务组织方式；双机协议原 A–D 是历史工程阶段，报告须注明所用含义。

下一轮建议交付范围为 T00–T04。文档整理后用户已授权开展基础工作；当前选择 Marko 并试跑独立 D 任务，T01–T04 整体验收尚未完成。

## 5. 四项决定与最有信息价值的验证

**真实场景。** 首选独立代码维护与文件/终端任务，已选 Marko 作为首个项目，实际用户任务与反馈来源仍需建立。通过多个程序结构、测试、文件状态和构建结果形成客观反馈；改文件名或替换排序/求和输入不构成新的程序族。先在 D 校准难度和检查器，形成基线有改善空间的任务。

**训练样本。** 当前 `src/coevo/train.py` 的准入只支持已验证的 `write` 目标。完整轨迹应保留读取、执行、工具观察、纠错、恢复和正确停止的上下文，只监督经核验的正确 Assistant 行为。T04 先核对模板/token mask、工具解析及独立 Adapter 加载，再在匹配来源和监督预算下比较局部写入与完整轨迹，分别诊断优化设置；保留 W0 及旧能力面板。不把训练 loss 或参数哈希变化当作收益，也不先叠加复杂 LoRA 算法。

**周期自动化。** 当前缺少训练产物时返回 `awaiting_user_training`，属于暂停后的有意边界。未来可由外部研究控制器按冻结策略调度训练、G 评价及回滚，触发方式仍待确认；待评估模型不得改准入和发布规则。现行 `rsi.py` 使用 `State()` 默认 `.state/rsi.sqlite`、固定周期与版本编号，不能据此声称独立实验流已隔离。新流在开展前须隔离权威状态、工作区、检索索引和版本命名空间，保留旧试跑库不覆盖。

**统计规模。** 原模型在旧/新合成面板分别为 3/3，存在天花板。先在 D 建立有效任务和难度分布，再依来源簇、流间方差及成本冻结 H 规模。5 pp 与 120–480 来源簇仅为未校准参考；正式四项优越性比较、Holm 和联合风险约束继续按评估协议执行。

当前不启动新底座重训、Titans/HOPE/TTT、全套抗遗忘算法复现、完整 RSIGym 云服务栈或笔记本量化。是否引入由实际学习容量、泛化、遗忘和部署瓶颈决定。
